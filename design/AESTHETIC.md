# BlockHabit 设计理念（Aesthetic Manifesto）

> 本文件回答"为什么长这样"。所有具体数值在 `TOKENS.md` / `ART.md` / `SURFACES.md`，这里只讲**判断依据**。
> 判据来源：2026-08-22 原始设计文档、2026-09-30 优化方案、2026-10-03 体验评审，以及代码事实抽取。
> 口径：**当本文件与代码冲突时，以本文件为准修代码；当本文件与用户明确要求冲突时，以用户为准并新增记录。**

---

## 1. 一句话定位

> **BlockHabit 不是待办清单，是一张会随坚持一起长大的桌子。**
> 你每天做的事变成一块积木，落在桌面上，按蓝图层层咬合，最后成为一座能被看见的建筑。

这句话决定了所有设计取舍：**"看得见的积累"优先于"更高的效率"。**

---

## 2. 三个隐喻（一切视觉决定的源头）

### 2.1 实物隐喻 —— 屏幕上的东西都是"可以拿起来的"
积木有体积、有凸点、有重量、会掉在桌上弹一下、落地会有接触阴影。因此：
- 容器不是"矩形区域"，是**有圆角与厚度的块**（`--r-lg` 20px + 极软阴影）。
- 按钮不是"文字区域"，是**可按压的积木**（按下 0.97 缩放、回弹）。
- 级联不是靠阴影叠层，是靠**黑白反转与留白**——实物世界里，白的纸、黑的墨，就够表达层级了。

> 反推：任何"网页味"的东西（直角边框、下划线链接、Material 涟漪、小字号说明文字堆叠）都是对这个隐喻的破坏。

### 2.2 仪式隐喻 —— 一天只有一次"落块"
打卡不是勾选，是**把一块积木放到它该在的位置**。因此：
- 打卡有完整的三段表演：慢落 → 着地压扁 → 回弹，外加声音与轻震动。
- 撤销是高成本动作（要确认），因为实物世界里"拔掉一块已砌好的砖"不轻。
- 全勤日、连击里程碑、建筑落成各有一次性的仪式动画，**绝不循环播放**。
- 每天的仪式只演一次，重复播放会让仪式贬值。

### 2.3 时间形状隐喻 —— 坚持是有轮廓的
- 日历热图：近 13 周，用灰阶点亮，"全完成日"才允许满亮。
- 建筑本身是时间的形状：190 块的城堡 = 190 天。
- 统计页不是仪表盘，是**这本手账的目录**（连击、最长连击、随笔、月度画报）。

> 反推：不要把统计做成分数、等级、虚拟货币。那会把"时间的形状"替换成"游戏系统的数字"。

## 3. 黑白为骨的五个理由

1. **把唯一的颜色留给奖励**：**每个主题只有一枚点缀色**（纸白/墨黑=琥珀 `#f5b301`，燕麦=赤陶 `#c25e3e`，雾灰=天蓝 `#0284c7`），所以点缀色出现＝有好事发生。颜色一旦泛滥，奖励信号就消失了（A1）。
   > D1 决议（D-20261110-048）：公理约束的是「**同一时刻只有一个点缀色相**」，不是「全应用只能是琥珀」。主题各自携带自己的点缀色，与 §2「主题可换而不换气质」一致。
2. **主题可换而不换气质**：纸白/墨黑/燕麦陶土/北欧雾灰四套主题，全部只改"无彩度阶"与"点缀色色相"，不改视觉语法。用户可以按心情换皮，但产品永远是同一个产品。
3. **让积木自己发光**：等距积木的三面明暗（顶亮/左中/右暗）本身就是最强的视觉焦点；任何彩色背景都会跟它抢注意力。
4. **长时段使用不疲劳**：这是一个每天要用 10 秒、连用 200 天的应用，高饱和与高对比会累积疲劳。
5. **印刷感/手账感**：黑墨与纸白，与"月度画报""拍立得""镌刻铭文"这些实体印刷隐喻天然一致。

## 4. 参考谱系（我们像谁、不像谁）

| 来源 | 我们借了什么 | 我们没借什么 |
|---|---|---|
| 乐高 / 磁性积木 | 圆角方块、顶部凸点、咬合感、色块纪律 | 高饱和玩具色、品牌 logo、角色 IP |
| 瑞士平面设计 / 包豪斯 | 网格、1px 线、无装饰、字号层级 | 极端非对称、冷峻的展览海报感 |
| Apple HIG（近年版） | 分层浮动弹窗（sheet + 独立滚动主体 + 常驻底栏）、inset grouped 表单、segmented control、触感微动效 | iOS 的毛玻璃滥用、系统级蓝、SF 字体 |
| Things 3 / Linear | 克制的留白节奏、动词式文案、无边框卡片 | 高信息密度、键盘优先的极客感 |
| Duolingo / Habitica | 只借"即时正反馈"的回路结构 | 用 gamification 的虚拟货币/等级/排行榜替代真实成长 |

## 5. 明确**不做**的事（设计边界，越界需新增记录并人工批准）

- ❌ **不做社交**：无好友、无排行榜、无分享到社区（本地导出图片是唯一出口）。
- ❌ **不做彩色主题**：新主题只能是无彩度阶 + 点缀色的重新组合。
- ❌ **不做虚拟货币/等级/成就徽章**：奖励只有积木、建筑与铭文。
- ❌ **不做推送型营销**：提醒只能是用户为自己设的。
- ❌ **不做必须联网的主路径**：A7。
- ❌ **不做假数据**：空态就显示空，不伪造进度、不预填演示数据（`?demo-castle` 仅开发用）。
- ❌ **不用 emoji 当图标**：图标一律积木风 SVG（`src/components/Icons.tsx`）。
- ❌ **不引入 UI 组件库**：现有组件与 `ui.css` 体系是资产，引入第三方库等于换掉视觉语法。

## 6. 张力与取舍（设计上真实存在的矛盾）

| 张力 | 现状 | 判断 |
|---|---|---|
| **极简 vs 功能蔓延** | 产品已长到 30+ 设置项、三页 + 7 个弹窗 + 展台/画报/拍立得/镌刻/透视考古 | 极简必须在**默认状态**里实现：默认界面只露必要项，进阶功能收进"探索/实验室"分组。设置项本身不该减少（用户已依赖），但**首屏不能变复杂** |
| **实物感 vs 性能** | 精灵缓存 + 圆角 + 凸点 + 接触阴影 + 植被 | 性能不足时优先砍"环境装饰"（植被、粒子），不砍积木本体与落块物理——本体是产品承诺 |
| **奖励强度 vs 真实成长** | 连击每 7 天一块 bonus、全勤送全勤块、修复砖补卡 | 允许"宽容机制"（修复砖、温和风化），因为它们服务于**长期留存**；不允许"通胀机制"（多打多送块） |
| **黑白纪律 vs 信息可读性** | 进度条三色（灰/蓝/绿）、危险红是既有例外 | 例外只允许存在于"状态语义"（完成/进行/危险），且必须来自令牌，不允许新色相 |
| **通用桌面 vs 移动** | 同一份代码双形态（`detect.ts` 判定 + `mobile.css`） | 移动端是"看与打卡"，桌面端是"建造与欣赏"；不要用一套布局强行兼容 |

## 7. 现状强度评估（2026-11-10）

**已经做得很好、不要动的地方**
1. 等距积木渲染体系（三面着色 + 圆角 + 凸点 + 接触阴影 + sprite 缓存）是产品最强的视觉资产。
2. 四主题令牌化彻底，主题切换有能力覆盖到 canvas（`paletteFromDocument`）。
3. 落块物理动画的三段式表演与音效材质系统，仪式感完整。
4. 黑白 + 唯一点缀色的纪律在 90% 的界面成立。
5. 本地优先 + 手动导出 + WebDAV 合并的数据模型，克制且诚实。

**最脆弱、最容易崩的地方（设计债在此）**
1. **例外太多且散落**：进度条三色、危险红、硬编码 `#f59e0b`、画布内联文案——每一条都可能是下一个"纸白主题白屏"级事故。
2. **首次启动没有任何引导**：公理说"看得见的积累"，但新用户第一次打开看到的是空列表，看不到那张桌子。
3. **第 191 天之后没有故事**：12 座建筑约 1400+ 块，但不告诉用户"之后还有什么"。设计上缺少"长期承诺的表达"。
4. **设置面板承担了太多产品决策**：30+ 项开关意味着"产品没想清楚默认值"。
5. **动效数值没有集中管理**：时长/缓动散落在组件与画布里，无法形成体系，也无法统一响应 `prefers-reduced-motion`。
