## 背景与问题

D-20261126-122 之后，桌宠已经由蓝图积木逐块拼成，但沿用建造页的 **3/4 等距视角**：`pet-cat` 的 12 块在屏幕上排成一条斜向队列，左前脸朝下、右脸朝右，读不出「这只猫正面对着你」。用户要的是**正脸面对用户**的桌宠。

桌宠与建筑是两种不同的对象：建筑要「可以绕着看的一件东西」，所以等距是它的语言（A3）；桌宠是「一只看着你、跟你互动的角色」，正脸才是它的语言。此前把两者强行共用一套投影，是这次问题的根。

## 设计决定

- **桌宠单独一套正交正视图**（用户指定方向）：新增 `paintBlueprintPet` 的正面投影，与建造页等距投影并存，互不替代。建造页、展台、图鉴缩略图**仍全部走等距**，A3 的「不允许第二套透视」指的是建筑场景，桌宠角色不计入——本条在 ART.md 的归属注释中登记。
- **投影公式**（正交、无透视缩短）：
  - 屏幕横向 `sx = x · U`，进深 `sy = y · V`，高度 `− z · blockH`；
  - `U = tileW/2`（24px，一格横向 24px，两块并排不重叠也不留缝）；
  - `V = tileH · 0.7 ≈ 16.8px`（一格进深在屏幕上的纵向位移，**只保留轻微俯视**以看清顶面与凸点，远小于等距的 24px）。
- **只保留轻微俯视**：`V/U = 0.7`，顶面以约 16.8×24 的扁菱形露出，凸点（rx 12 / ry 6）仍能读出圆点。若 `V=0` 完全平视，顶面与凸点全部消失，积木退化成平面方块、黑白主题下一片灰。
- **积木仍是蓝图块**：逐块调用 `isoCube.drawCube`，外形 / 单位 / 明暗全部复用，不新增任何手写几何（延续 D-20261126-122 的结论）。
- **画家排序**：先按进深 `y` 升序（远的先画），再按 `x`、`z`。正视图下不存在等距的「先 x+y 后 z」。
- **走动摇摆收敛**：`PetPose.turn` 的左右转身幅度由建筑视角的 ±45° 收敛到正视下的 ±12°（`PET_FRONT_MAX_TURN`）。正脸为主，走动时只是肩部轻轻摆，不做左右各转 45° 的「甩头」。
- **黑主题可分**：块身沿用 `deriveShading` 的三面明暗（顶 > 左 > 右恒定，ART §2），正视下右脸仍比左脸暗一档，凸点顶面 `studTop` 提亮 8%；不新增颜色、不加发光。
- **凸点齐全**：每块顶面画圆柱凸点（侧裙左半 `leftA` / 右半 `rightA`、顶面 `studTop`、左上高光弧），与 ART §3 同参数；上方有块或该块属于脸面时不画——后者避免凸点戳在额头上。
- **五官**（新增 `PET_FACE_REGIONS` 显式声明每只桌宠的脸画在哪一层，不用「最高层」启发式——猫的双耳在 z=2、机器人的额部在 z=3，启发式都会把脸画到耳朵/额头上）：
  - **猫**：竖胶囊眼（沿用 D-20261125-113）+ 三角鼻 +「ω」嘴 + 每侧两根胡须，全部用 `--ink` 与 `withAlpha(ink, 0.75/0.4)`；
  - **机器人**：内缩的屏幕底板（`rightB`）+ 两点眼 + 一格嘴，happy 时嘴向上弯；
  - 未知蓝图回退到「最靠前一行里最长的连续段」，保证任何桌宠蓝图都有脸。
- **动作与表情**：`mood`（idle / focus / ready / happy）与 `blinking` 从 `PetWindow` 现有的眨眼、跳跃、拖拽 bump 状态传入，与手写几何同一套；happy 弯眼、focus/眨眼压成一条线、ready 放大。跳跃抬升、落地压扁、接触阴影变淡变大全部沿用原 `PetPose`。
- **走动摇摆**：`turn` 不再转体，改为 `transform(1,0,lean,1,0,0)` 的斜切，上限 `PET_FRONT_LEAN = 0.055`（约 3°）；手写几何的 `projectPet` 也把转身幅度收敛到 `FRONT_TURN_LIMIT = 0.265`（原 ±45° → 约 ±12°），避免「蓝图正脸、未建成时的 block 形象却在甩头」。

## 取舍与被否方案

- **否掉「只给等距投影加一个固定 yaw」（本轮最初方案）**：实验页在 96×128 真尺寸下把 yaw 试到 0°/8°/12°/15°/22°/30°/45°，两种做法都失败：
  - 旋转**蓝图排列**、继续贴 45° 烘焙的立方体精灵：相邻积木的菱形剪影互相咬边（`yaw 0°` 时并排两块下半身重叠约 1/3），出现「积木被切掉一块」的假象；`yaw 15°` 仍然倾斜，看不出正脸。
  - 旋转**精灵本身**：`drawCube` 是按 45° 方位角烘焙并走 LRU 精灵缓存的，旋转位图会让 1px 描边糊成 2px 灰边，黑主题下尤其明显。
  - 结论：正脸不是「在等距上拧一个角度」能得到的，必须换投影。
- **否掉完全平视（`V = 0`）**：顶面为零面积，凸点画不出圆，积木只剩一块正面矩形，失去 A2「圆润积木与凸点」的形态语言；黑白主题下相邻块之间只剩 1px 分界，糊成一片。
- **否掉「桌宠也用等距，但把蓝图改成正面造型」**：那要改 `generatorsV4.ts` 的建筑数据（受 D-20261124-081 保护），且要重建用户已拼好的蓝图，代价远大于换投影。
- **否掉给桌宠换成 2D 平面插画**：失去积木的三面明暗与凸点（A3 的形态语言），也无法跟随主题与材质色。

## 影响面

- 渲染：`src/render/petBlueprint.ts` 增加正面投影与正脸排序；`src/render/petCanvas.ts` 的 `projectPet` 手写几何同步收敛转身幅度（未建成蓝图时的 block 形象也应是正脸，不能一个正一个斜）。
- 事件与窗口：不动 `PetConfig`、不动窗口尺寸（仍 96×128 透明窗）、不动走动/跳跃/拖动逻辑。

## 验收标准

- `?pet-preview=1&skin=cat&blueprint=pet-cat` 截图：猫的正面 vs 旧 3/4 斜视并排对比，正脸能一眼看出「面对用户」；耳朵在顶部左右各一只、身体居中。
- `pet-bot` 同样成立：两条手臂左右对称外伸，躯干正对观众。
- 猫有眼睛 / 鼻子 / 胡须 / 嘴；机器人有屏幕脸与嘴；眨眼与 happy / ready / focus 三种表情都可见。
- 纸白与墨黑两个主题下：能分辨凸点、顶/左/右三面明暗，不糊成一片（像素抽检：右脸亮度低于左脸、凸点顶面高于块顶）。
- 走动中间帧：转身幅度 ≤ ±12°，不出现左右各 45° 的甩头；画布最左/最右列非透明像素数为 0（无细线）。
- `npx tsc --noEmit` 零错误；`npm test` 全绿（新增正脸投影的几何/像素边界测试）；`npm run design:check` 与 prettier 通过。
- 桌面实机：`npm run tauri build -- --no-bundle` 后启动 `src-tauri/target/release/blockhabit.exe`，桌宠窗口内为正脸、走动无细线。
