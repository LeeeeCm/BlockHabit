## 背景与问题

桌宠窗口当前固定为 160×180 逻辑像素。角色正视宽约 30 个等距单位、高约 39 个单位；在默认「中」尺寸下实际只占约 50×57 像素，窗口四周留下大片透明区域。透明窗口仍会接收鼠标事件，导致桌宠周围约 3 倍于角色的范围无法点击到下层应用，也影响拖动时的空间判断。用户反馈「透明小框太大，只需要比桌宠大一点」。

## 设计决定

- 桌宠窗口从 **160×180** 收紧为 **96×128** 逻辑像素；`PET_SIZE` 与 `tauri.conf.json` 的 `pet` 窗口保持一致。Windows 对带 `WS_THICKFRAME` 的窗口有约 136px 的最小宽度，创建时会把 96px 撑宽，因此在 Rust `setup` 中于窗口隐藏阶段显式 `set_size(96×128)`，与前端 `PET_SIZE` 一致。
- 重做取景：脚底锚点从垂直居中改为距窗口底部 **10px**，把原本落在窗口下方的空白收回；缩放上限改为按真实最大角色宽度 `tileW`（而不是 `2 × tileW`）计算，并为「大」尺寸的 1.05 倍、跳跃抬升与凸点预留空间。
- 保持三档尺寸的角色语义不变：小 0.8 / 中 0.9 / 大 1.05；以「大」尺寸仍不裁切为约束，三档共用同一窗口。
- 保留原跳跃高度、左右转体、待机张望/伸懒腰/小跳与顶部打卡气泡；气泡继续贴在窗口顶部 8px 处，宽度按文本自适应。
- 右键面板仍按桌宠窗口的实时外框定位，不写死偏移。
- 接触阴影半径同步收小（`tileW × 0.6` / `tileH × 0.45`），避免阴影在窄窗口左右被切出硬边。

预期角色占比（默认中号）：正视约 48×54px（含柔和阴影约 48×59px）；三档实测大号正视约 56×63px、侧身跳跃最宽约 78–83px，窗口 96×128px 仍不裁切。窗口面积由 28,800 减到 12,288 逻辑像素（约减少 57.3%）。

## 取舍与被否方案

- **否掉只放大角色、不缩窗口**：视觉上角色会变大，但透明命中区仍是 160×180，用户指出的实际使用问题没有解决。
- **否掉逐像素点击穿透（`setIgnoreCursorEvents` + alpha 命中）**：需要持续在主进程与前端之间同步指针区域，拖动、气泡与高 DPI 下都容易抖动；本次先用矩形收紧解决 80% 问题。
- **否掉把窗口压到角色静止外框（约 80×90）**：跳跃抬升、侧身转体与三档尺寸会裁切，且右键气泡没有位置。
- **接受接触阴影外缘被窗口底部裁掉一部分**：阴影本身是向外淡出的柔和渐变，裁掉的是接近 0 的最外层；同时把桌宠阴影半径收小，换取更小的命中区。若实机出现硬边，再单独调整阴影半径。

## 影响面

- `src-tauri/tauri.conf.json`：`pet` 窗口宽高。
- `src-tauri/src/lib.rs`：启动时强制 96×128，绕过 Windows 最小窗口宽度。
- `src/platform/petMotion.ts`：`PET_SIZE`，影响默认位置、边缘钳制、自主走动边界。
- `src/render/petCanvas.ts`：`petStageFloor` 与 `paintPet` 的取景比例，影响桌宠绘制，不影响建造页等距渲染。
- `src/render/petCanvas.test.ts`：新增脚底锚点与三档尺寸不越界的布局契约测试。
- `README.md`：桌宠窗口尺寸说明。
- 需人工走查：三种形象 × 三档尺寸 × 静止/跳跃/待机动作；右键面板贴合位置；多显示器缩放。

## 验收标准

- `pet` 窗口实际外框为 96×128（100% 缩放）；`PET_SIZE` 与配置一致。
- 在浏览器 `?pet-preview` 中对 block / cat / bot × small / medium / large × 静止与跳跃峰值做像素包围盒检查，角色与气泡不越出画布；脚底位置在尺寸切换时不变。
- 窗口四周不再出现超过角色外沿约 20px 的透明横向死区；右键面板仍能贴在桌宠旁边。
- `npx tsc --noEmit`、`npm test`、`npm run design:check` 通过。
