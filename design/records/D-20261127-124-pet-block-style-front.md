## 背景与问题

D-20261127-123 把桌宠改成正视，但外形仍是**蓝图逐块复刻**（`pet-cat` 12 块 / `pet-bot` 16 块）。放到 96×128 的小窗里暴露三个问题：

1. **不好看**：十几块 24px 的小方块挤在一起，轮廓碎、噪声大，脸被压在三格宽的缝里，胡须细到糊成一团。
2. **太大**：为塞下整座蓝图，取景把 96×128 撑满，角色顶到窗顶、脚贴窗底，没有呼吸空间。
3. **画风不一致**：用户真正认可的「积木桌宠」是原本手写的那套 —— **一整块圆角积木 + 顶上一枚圆柱凸点 + 简单五官**（`petCanvas.ts` 的 `block` / `cat` / `bot` 模型）。蓝图版是「小积木堆成的模型」，和它不是一个语言。

用户明确表示：**不再要求桌宠和蓝图一样**，要的是积木桌宠的画风，凸点也要和积木桌宠一致。

## 设计决定

- **外形按蓝图网格摆置，块与块合并成整板**：形体用「格 / 层」描述，逐格对照 `generatorsV4.ts`：
  - `pet-cat`：身体 **x0..2、z0..1（3 格宽 2 层高）**；**双耳在顶层 x0 与 x2，中间空一格**（`put(0,1,2)(2,1,2)`）；**尾巴在后排，从身体右缘横伸一格、尾尖升到第 2 层**（`fill(1,3,0,0,0,0)` + `put(3,0,1)`）。
  - `pet-bot`：身体 **x1..2、z0..3（2 格宽 4 层高）**；**手臂在第 2 层向左右各伸一格**（`put(0,1,1)(3,1,1)`）；**额部**在最顶层（`fill(1,2,1,1,3,3)`）。
  - 与蓝图唯一的差别：不再把相邻格画成一个个小立方体，而是**同高同排的相邻格合并成一块整板**，于是正面是一整张连续的脸（不被方块缝切开），轮廓仍与蓝图一致。
- **绝不出现三角**：耳、尾、臂全部是有宽有高的矩形 slab，只保留 ≤3px 的小圆角（ART §3 的圆角档位）。
- **顶面一枚凸点，参数与 `petCanvas.paintStud` 完全相同**：`rx = tileW×0.25`、`ry = rx×(tileH/tileW)×2×FRONT_PITCH`、高 `STUD_H = 5`；侧裙左半 `leftA` / 右半 `rightA`（竖向 clip 分色）、顶面 `studTop`、左上 `white@0.6 / 1.2px` 高光弧。**不复刻蓝图里「每块一个凸点」的排布**——那正是噪声来源。
- **正脸朝向，且只保留纵向俯视**：正交正视相机，**横向进深位移必须为 0**（`PET_FRONT_DEPTH_X = 0`）—— 第一版给了 `tileW×0.17` 的横移，整块积木立刻变成平行四边形、读作「躺倒的盒子」，是本次返工的主因。纵向进深取手写积木桌宠的 `FRONT_PITCH = 1/(2√2)`（一格只抬 8.49px），顶面读作一条窄檐而不是大盖子，凸点也因此与手写版同样扁平。
- **尺寸缩小**：宽度通常是约束方（96 宽的窗里方头桌宠很容易顶满），所以**宽高共用一个留白系数** `PET_FRONT_FIT = 0.85`（占可用空间 85%），并把绘制上限收到 `PET_FRONT_MAX_SCALE = 2.2`。实测猫 74×64 → 约 63×55，四周有明确留白。
- **动作与表情两只都接上**：跳跃抬升 + 接触阴影变淡变大、落地压扁（`petHopPose` 的 scaleX/scaleY）、走动侧倾、眨眼、happy / focus / ready 三种表情。全部由 `PetWindow` 同一套 `pose` / `mood` / `blinking` 驱动，猫和机器人共用同一渲染入口，不存在「只有一种有动作」。
- **走动摇摆**：保持 D-20261127-123 的收敛幅度（斜切 ≤ 0.055），不做甩头。
- **只读蓝图的 `id`，不读它的块列表**：`pet-cat` → 猫形，其余 → 机器人形（未知 id 也能画，不会空）。蓝图网格是**按内容手工对齐**到 `generatorsV4.ts` 的常量，改蓝图需同步改 `petSlabs`。

### v3：可爱化（用户反馈「太诡异」）

上一版按蓝图网格精确摆位后，形状对了但**读起来仍是诡异**，原因逐条定位并修掉：

| 诡异来源 | 处理 |
|---|---|
| 猫头顶一枚凸点插在双耳之间 | 猫**不画凸点**（手写积木猫本来就没有，耳朵就在头顶）；只有机器人露一枚 |
| 三角鼻 + ω 嘴 + 胡须在 96px 里糊成一团 | 全部删掉，只留**两只竖胶囊眼 + 一个微笑弧**，与手写积木桌宠同一个画法 |
| 五官太小、偏上，下巴空一块 | 眼睛按身体尺寸放大到 0.115 系数、脸在孩子面里居中（`0.52`） |
| 机器人是 2×4 的瘦高柱 + 一整块深色屏幕 | 高度收到 **3 层**（方头 2 层 + 躯干 1 层）；**去掉深色屏幕底**，改用同一张可爱脸；手臂收成短手 |
| 方角生硬 | 圆角按短边 18%（上限 6 世界单位），读作塑料积木 |
| 窄身体上顶着大圆顶 | 凸点半径按身体宽度收（`min(tileW×0.25, 宽×0.3)`） |

机器人「机器感」不再靠暗色屏幕，而是靠**嘴更横**（一小段横杠）与头顶那枚凸点来区分。

## 取舍与被否方案

- **否掉继续修蓝图复刻版**（上一轮的做法）：把 12~16 块塞进 96×128，怎么调都是「一堆小方块」，与积木桌宠的单块语言冲突。用户已明确放弃「必须和蓝图一样」这条约束。
- **否掉完全丢弃蓝图（只用 skin 设置）**：`completedBlueprintIds` 里的 `pet-cat` / `pet-bot` 仍是用户解锁的成果，保留「建好哪只是哪只」的关联，只是不再逐块复刻外形。
- **否掉保留每块凸点**：蓝图版视觉噪声的最大来源；积木桌宠只有顶面一枚凸点，统一它才能「画风一致」。
- **否掉用 CSS 缩小 canvas**：96×128 是窗口尺寸（`src-tauri/tauri.conf.json` 与 `PET_SIZE`），改窗口会牵动走动/拖拽/多显示器坐标；在绘制里留白更安全。

## 影响面

- 渲染：`petBlueprint.ts` 从「蓝图逐块」改为「单块积木 + 耳/尾/臂 + 五官」；`petBlueprint.test.ts` 的断言随之从「块数一致」改为「单块 + 一枚凸点 + 留白比例」。
- 尺寸：`PET_FRONT_FIT` 控制角色占窗高的比例；三档 `petSizeScale` 仍在外层缩放，不冲突。
- 不变：窗口尺寸、走动/跳跃/拖拽、`pet-config` 事件、主题与材质色派生。
- 走查：纸白 / 墨黑两个主题、猫与机器人、静止与走动中间帧。

## 验收标准

- `?pet-preview=1&skin=cat&blueprint=pet-cat` 与 `?pet-preview=1&skin=bot&blueprint=pet-bot`：外形与手写积木桌宠同语言 —— **一整块圆角积木、顶面一枚凸点、正面一张完整脸**。
- 角色高度约占窗口 72%，上下留白明显，不再顶天立地。
- 凸点的 `rx/ry/高度/分色/高光弧` 与 `petCanvas` 的手写凸点一致。
- 猫：竖胶囊眼 + 三角鼻 +「ω」嘴 + 两侧胡须；机器人：屏幕脸 + 两点眼 + 一格嘴；眨眼与三种表情可见。
- 2 个主题下三面明暗清晰，不糊成一片；走动中间帧只轻微侧倾。
- `npx tsc --noEmit` 零错误；`npm test` 全绿；`npm run design:check` 与 prettier 通过。
- 桌面实机：重新编译后 96×128 窗内为缩小后的正脸积木桌宠，边缘无细线。
