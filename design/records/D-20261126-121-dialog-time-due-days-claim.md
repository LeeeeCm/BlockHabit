## 背景与问题

三件事：

1. 新建习惯的「到点提醒」还是旧的 ±1 小时 / ±15 分钟步进器，与设置页「晚间收尾提醒」的时间滚轮不一致。
2. 设了指定星期（例如只勾周一）的习惯，在周二到周日仍然出现在今日列表里。
3. 当天已领过全勤积木后，再新建一个习惯并完成打卡，页面又亮出「领取全勤积木」—— 点下去才提示「已经领过了」。

## 设计决定

- **复用时间滚轮**：删掉 `HabitDialog` 里的 `TimeStepper` 与 `shiftHHmm`，开始/结束时间都换成 `TimeWheelPicker`（与设置页同一个组件、同一套点击展开 + 滚轮步进）。附带好处：分钟粒度从「15 分钟栅格」变成逐分钟，与 Apple 闹钟一致。
- **指定星期过滤**：今日页新增 `dueActive`（`filteredActive.filter(h => isHabitDueOnDay(h, day))`），分组、今日完成数分母、全勤判定、今日简报全部改用这一集合。`habitMetOnDay` 的「休息日免战」语义保留（历史统计/热图仍按原口径），只是**今日列表里不再出现**。
- **全勤只领一次**：`canClaimDay` 把「今天领过没有」提到最前面判断（事实优先于状态）；今日页把卡片显示条件收成 `allMetToday`，`claimed` 单独从 `dayClaims` 取，领取后按钮文案变为「已领全勤」，不会再出现可点的「领取」。

## 取舍与被否方案

- **否掉「休息日仍显示但置灰」**：用户明确要「别的星期不要出现」；置灰仍占位，还让列表显得很长。
- **否掉改 `habitMetOnDay` 的休息日语义**：那会让历史热图、年鉴、连击的计算口径一起变，属于数据口径变更；本次只改「今日显示集合」。
- **否掉「领过之后再建习惯就补发一块」**：全勤奖励的语义是「今天所有事都做完了」，一天一次、不可追加；追加会让「多建习惯」变成刷块手段（A6 数据诚实）。
- **否掉给时间滚轮再写一套「习惯弹窗专用」变体**：同一个交互两套实现必然漂移。

## 影响面

- 界面走查：新建/编辑习惯的提醒段（开启后出现两个滚轮 + 结束时间可选）、今日页指定星期习惯的可见性、今日完成数、全勤卡。
- 统计口径：今日完成数分母改为「今天该做」的习惯数；历史热图/年鉴不变。
- 无障碍：滚轮仍是 `spinbutton`，键盘可操作。

## 验收标准

- 习惯弹窗的提醒时间与设置页同一控件、同一交互；可以设到任意分钟。
- 只勾周一的习惯在周四的今日列表里不出现，且不计入今日完成度分母。
- 当天已领全勤后，再完成任何新习惯：卡片不再出现「领取」按钮（显示「已领全勤」），`canClaimDay` 返回 `already`。
- 次日可正常领取。
- `npx tsc --noEmit`、`npm test`、`npm run design:check` 通过。
