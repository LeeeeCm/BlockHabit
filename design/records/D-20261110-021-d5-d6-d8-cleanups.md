## 背景与问题

审计把一批「不影响功能、但会让后来者误判」的残留归为 D5 / D6 / D8（P2–P3）。三条的共同特征：**代码告诉你的和实际发生的不一样**。

| 编号 | 问题 |
| --- | --- |
| D6 | i18n 残留：8 个从未被读取的死键、4 处 `t.nav?.x ?? '今日'` 兜底（等于让 `nav` 不可用时静默显示中文）、`Today.tsx` 一处 `lang === 'zh' ? ... : ...` 内联三元（违反 AGENTS §3.4） |
| D8 | **蓝图名双源**：`generators.ts` 里 12 个中文名（`灰岩城堡` 等）从未被任何代码读取，真源是 i18n；且 7/12 与实际显示名不一致，谁读谁错 |
| D5 | 9 条死 CSS（`.day-check` 六条 + `.fab` 三条，全仓库零引用）、1 处死枚举 |

## 设计决定

### D6-a：删除 8 个死键（先证明再删）
写了脚本递归解析 `i18n/types.ts` 的接口路径（427 条），再对全 `src` 做 `t.<path>` 匹配，得到 16 个候选。逐个核对后：
- **动态访问的必须留**：`today.periods.*`（`t.today.periods[p]`）、`microMood.*`（`t.microMood[m]`）→ 保留；
- **真死键 8 个**：`common.archive`、`gallery.blocks/switchTarget/currentTarget`、`tray.pendingLabel/allDoneLabel`、`reflections.chronicleTitle/Subtitle` → 从 `types.ts` / `zh.ts` / `en.ts` 三处同步删除。

### D6-b：今日页标题去三元，改为语义化日期键
原来 zh 分支手写 `{m} 月 {d} 日` + `周{weekday}`，en 分支调 `dateHeader(...)` —— 两套写法、只为让星期显示成小号灰字。新增两个键：
```ts
monthDay: (month, date) => string      // zh: 11 月 10 日 / en: Nov 10
weekdayLabel: (weekday) => string      // zh: 周二 / en: Tue
```
标题改为 `{t.common.monthDay(...)}` + 灰字 `<span>{t.common.weekdayLabel(...)}</span>`，**布局与字号完全不变**，三元消失。

### D6-c：去掉 4 处 `?? '今日'` 兜底
`BottomTabBar` 的 `t.nav?.today ?? '今日'` 看似稳妥，实际让「nav 缺失」这种 bug 静默降级成中英混杂。改为 `t.nav.today`，缺失时由 TypeScript 报错。

### D8：删除 `Blueprint.name` 死数据
`Blueprint` 的 `name` 字段只被 `generators.ts` 的 `build()` 写入，全仓库**零读取**。删除：type 字段、`build()` 的 `name` 参数、12 处调用点的中文名实参（`b.build('castle', '灰岩城堡', 4, 4)` → `b.build('castle', 4, 4)`）。蓝图显示名从此**只有 i18n 一个源**。

### D5：删除 9 条死 CSS
`.day-check`（6 条）与 `.fab`（3 条）在全仓库（ts/tsx/html/css/rs/json）零引用，删除。`ui.css` 的**硬编码 hex 从 2 个降为 0**（上一轮 C3 已把两处 `#ffffff` 换成令牌）。

## 取舍与被否方案

1. **否决「删除死枚举 `soundMaterial: 'mute'`」**：审计称其为死枚举，但实测它**有真实实现**（`playSnapSound` 的静音分支）、**被 sanitize 识别**（`adapter.ts`）、**且有专门测试**（`innovations.test.ts`）。删它就必须连带删掉一条已覆盖行为的测试 —— 那正是 AGENTS §6 明令禁止的「改测试让代码变绿」。改为保留，并在本记录里写明它是「可编程静音档，UI 未暴露」。
2. **否决「用一个 `dateHeader` 顶替整个标题」**：`dateHeader` 返回单一字符串 `11 月 10 日 周二`，无法把星期做成小号灰字；且 en 的 `dateHeader` 是 `Nov 10, Wed`，冒号分隔符与设计不符。
3. **本轮未做「`setTimeout` 泄漏」**：全量扫描后有 13 个文件存在 `setTimeout` 无 `clearTimeout`，但**绝大多数是 toast 自动消失、动画结束回调这类一次性定时器**，无害；真正需要清理的是「组件卸载后仍 setState」的少数几处，需要逐个读上下文判断，不适合与本批合并。已作为独立条目留在计划里。

## 影响面

- 代码：9 个文件；净减少约 **60 行**（死键 24 行 + CSS 42 行 + 类型/参数 6 行）。
- 用户可见：**英文界面标题字号/分隔符一致；中文界面逐字符相同**（见验收）。
- 风险：删除死键/死 CSS 无运行时影响；`Blueprint.name` 删除后任何未来想读它的人会得到编译期错误而不是错误数据。
