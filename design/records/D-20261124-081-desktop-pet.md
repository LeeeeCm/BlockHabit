## 背景与问题

当前工作树的桌面入口是 `MiniDeskToy`：它把建造场景缩进主窗的摆件模式，没有单独的桌宠、正脸、右键面板或可换形象。用户希望它像建造页的一块实体积木：平时正面朝人，侧跳才转身，并能在不打开主页面的情况下查看待办、确认打卡。

保留 [D-059 的三档预设、拖拽和可选置顶](D-20261110-059-widget-tiers.md) 及 [D-064 的用户确认后落块](D-20261110-064-focus-companion.md)。本提案涉及桌宠正视投影和可独立选择的蓝图支线；按 [设计中枢 §4](../README.md#4-记录规范与状态机)，**人工审核将本记录置为 `approved` 后再改产品代码**。

## 设计决定

### 造型：安静时看向用户，侧跳才转身

- 默认是一块有圆角、凸点和接触阴影的积木。静止、专注和提醒时，正面水平朝向用户，不露另一张侧脸；眼睛和嘴始终落在同一块的同一面。上缘可以露浅顶面与凸点，以保留积木厚度，不把脸跨贴到棱上。
- 只在用户触发左／右短跳时朝相应方向侧身，落地压缩、回弹，随后回正。点击／方向键可触发，不让窗口自行游走。减少动态效果时保持静态正面，不影响操作和状态反馈。
- 默认、眨眼、专注、到点、达标微笑，靠眼嘴形状区分，不靠新增色彩或贴纸。未完成不变成责备表情；计数只加一步未达标时不用庆祝脸。待确认和达标仍有文字，表情不是唯一的状态信号。
- 正视是**桌宠专用的同材质相机朝向**，不是建造页的新投影。沿用 [ART §2–6](../ART.md#2-立方体三面着色模型isots180196由---block--派生) 的 `paletteFromDocument` / `deriveShading`、`roundedPoly`、凸点高光、轮廓和着地方式；斜向帧沿用建造页等距几何。四主题同源，不新增 CSS 伪 3D、渐变配方或颜色。面板按 [TOKENS §2、§4–6](../TOKENS.md) 使用 `--r-md`、`--fs-body`、`--surface`、`--ink`、`--line` 与既有间距，文案按 [VOICE](../VOICE.md) 补齐中英。

### 右键面板：点开才显示待办

- 在桌宠本体右键（或菜单键 / Shift+F10 / 可聚焦的菜单按钮）打开**桌宠右侧**面板。上部是今日未打卡的习惯及进度，下部是打开今日、桌宠设置、置顶／收起。无待办时说明已完成或今天无安排，不混淆尚未读档。长清单只在面板主体滚动；Esc、再次右键或关闭按钮收起，键盘焦点还给入口。
- 使用现有摆件窗口。手动打开时才扩大窗口；贴右屏边时临时向左挪整组，让面板仍在宠物右边，收起恢复原尺寸和位置。极窄工作区改为窗内上下排列。按显示器工作区避开任务栏；临时尺寸／位置不写入停靠记录。不复制托盘的独立浮窗，也不新增原生窗口权限。

### 形象：亲手搭好，才可选用

- 首发**积木**（默认）、**方块猫**（双耳与短尾）、**小机器人**（方头与短臂）。后两款是同材质积木拼出的角色，而非仅更换表情。新增 `pet-cat`、`pet-bot` 两份小体量蓝图，目标分别 **12 / 16 块**；由现有有效打卡落块，可在「建造 → 图鉴 → 桌宠蓝图」主动选为当前项目。它们不插入原 23 座的解锁顺序，不要求先完成主线，也不发额外积木。
- 「桌宠设置」展示形象、来源与 `已放置 / 总块数`，锁定态可前往对应蓝图。落成只使形象可选，不替用户切换。资格从当前已放置的有效块推导，不另存解锁旗标；撤销、删除或同步合并使蓝图未完成时，当前显示回退默认积木。设置只存用户选择，缺失或未知 ID 使用默认形象。
- 新蓝图独立注册为内容包 v4，沿用旧客户端在清洗前的内容版本门禁，不改变存档 schema。原 23 座坐标、容量、进度与展台解锁条件不变；涉及多设备同步时，旧客户端需要先升级才能继续读取新内容存档。

### 气泡：提醒不是替人打卡

- 日常列表用 `isHabitDueOnDay` + `habitMetOnDay`，不把休息日、已归档、已达标的项目混入待办。周目标未达但今日已记录时显示状态，不重复提供打卡按钮。
- 专注倒计时归零时显示「专注已到点」气泡，提供「确认打卡」和已有的延长入口。用户设置过的习惯提醒也可用气泡：合并同一批提醒，保留稍后能力。**不抢输入焦点、不自动打卡**；气泡在现有窗口内，不把窗口突然放大。若面板已打开，在同一面板内提示，避免重复浮层。隐藏时保留已有通知机制，不自动唤起窗口。
- 用户按操作键后再以当下日期、习惯、会话和实际记录复核：普通习惯显式打卡；计数只记配置的一步；专注未到点只能开始／继续，到点按实际分钟确认。显示成功须有真实记录 ID；只在 `habitMetOnDay` 由未达转达标时播放庆祝。不让旧气泡在跨日、撤销、同步或习惯失效后写错记录。

## 取舍与被否方案

- 不做持续侧身、脸跨两面、频繁巡游。个性放在表情和短跳，默认画面安静。
- 不做透明异形窗或第二套桌宠窗口。保留既有摆件能力，减小双屏、多 DPI、点击命中和焦点风险。
- 不做建成后永久发放的解锁凭证、养成分数、自动打卡或后台监控。形象与习惯数据保持可解释。

## 影响面与实施顺序

1. **造型和窗口**：在 `MiniDeskToy` / `components/minidesk` 加 Canvas 桌宠与菜单，复用 `isoColor` / `isoGeometry` / `isoGround` / `sceneMotion`。`platform/miniWindow.ts` 保持纯布局计算，`App.tsx` 管现有窗口的临时宽度与位置。先锁定正面、斜跳、减弱动态和面板定位的回归测试。
2. **蓝图和设置**：`logic/blueprints` 追加两份几何、目录和版本；`GalleryDialog` / `Build` 展示可独立进入的支线。复用 `buildingArchive` 的落成口径及现有设置持久化，在 `LabGroup` 提供选择。先测普通蓝图解锁无回归、进度／撤销／合并结果与未知形象的回退。
3. **气泡和打卡**：`App.tsx` 目前只在主窗分支挂载 `TimerWatcher`、`ReminderWatcher`。将两者放在水合后共用的生命周期中，保留单一时钟和去重，桌宠可见时由气泡承接。继续使用 `timerStore`、提醒队列和 `appStore.checkIn`，不另造计时器或写入器。先测显示／关闭无写入、明确确认才写、过期按钮安全失效。
4. **工程与发布边界**：沿用依赖锁文件，不添加依赖、提高应用版本或发布。按既有测试模式做 RED → GREEN，再做独立代码审查；记录补充美术和窗口规范后走设计校验。新存档不得拿旧版本直接覆盖测试。

## 验收标准

- 四主题中正面轮廓、顶凸点和眼嘴清晰可辨；左右各一段短跳只有跳中侧身，落地回正；减少动态时无位移／翻转。中英长文本不裁切。比较建造页与桌宠材质，而不是只查看组件截图。
- 三档尺寸右键／键盘打开和关闭；Windows 100% / 125% / 150%、右下角、负坐标副屏与双屏切换时验证不出工作区，关闭恢复位置；浏览器预览只验交互和排版，不替代真窗口验证。
- 旧主线顺序保持；两款蓝图有真实落块、落成后设置可选、撤回最后有效块后回退且不能继续选择。旧存档默认积木；v3 读取含新内容的 v4 存档应拒绝并保留原数据。
- 普通、计数、专注均只在有效操作后记录；零点或恢复时无重复通知，专注到点从泡泡查看和确认；关闭泡泡无打卡；跨午夜、归档／同步、计数未达标、今日已记录的周目标均有回归。面板与主窗共享事实，无额外发放积木。
- `npx tsc --noEmit`、`npm test`、`npm run design:check` 和 `npm run build` 通过；新增逻辑覆盖率目标 ≥80%。浏览器端走「选择蓝图 → 落成 → 换形象」和「到点 → 确认 → 待办更新」，另记真机测到的 DPI／多屏范围与未覆盖项。
