## 背景与问题

审计 U1（`D-20261110-004`）：2026-10-03 修好了「墨黑主题积木与背景同色」（右脸 `#0f0f0f` → `#1c1c1c`），但随后落地的「时段感知环境光照」在夜间把块面**再乘 0.55**：`#1c1c1c × 0.55 ≈ #0f0f0f`，与页面背景 `#0a0a0a` 的对比度只有 **1.03:1** —— 等于把那次修复完全抵消。

## 设计决定

### 1. 新增对比度工具（WCAG 2.x）
`iso.ts` 新增三个纯函数：`relativeLuminance` / `contrastRatio` / `floorContrast`。

### 2. 地板目标 = 「本主题标准光照下的原始对比度」
不是拍一个固定值，而是取**该主题在 noon（标准光照）下该块面相对 `--bg` 的对比度**作为下限：
```
floorFace = (base, dimmed) => floorContrast(dimmed, bg, contrastRatio(base, bg))
```
语义：**环境光可以让块面更亮，但不允许比标准光照更看不清。** 这样既保留了「夜晚更沉」的氛围，又不会出现「夜里建筑消失」。

### 3. 只对暗底生效
`floorContrast` 在 `relativeLuminance(bg) ≥ 0.2` 时直接返回原色 —— 浅色主题上块面变暗本来就是**对比度上升**，不需要兜底，也不该改动 oat / fog 既有的浅色面观感。

### 4. 生效范围
只作用于会被暗化的两个时段：**黄昏（dusk）与夜幕（night）**。晨曦只做提亮，正午为恒等变换，均不触发地板。

## 实测对比度矩阵（用真实函数计算，四主题 × 四时段）

| 主题 | 时段 | 左脸（前→后） | 右脸（前→后） |
| --- | --- | --- | --- |
| 纸白 | dawn/noon/dusk/night | 1.35 / 1.59 / 2.25 / 3.35（不变） | 4.00 / 3.31 / 6.21 / 8.23（不变） |
| **墨黑** | dawn | 1.59 | 1.13 |
| **墨黑** | noon | 1.50 | 1.16 |
| **墨黑** | **dusk** | **1.34 → 1.54** | **1.07 → 1.16** |
| **墨黑** | **night** | **1.23 → 1.52** | **1.03 → 1.16** |
| 燕麦 | 四时段 | 1.11 / 1.29 / 1.78 / 2.56（不变） | 8.34 / 7.33 / 10.90 / 12.76（不变） |
| 雾灰 | 四时段 | 1.13 / 1.35 / 1.96 / 3.03（不变） | 10.41 / 9.39 / 12.75 / 14.18（不变） |

**16 个「主题 × 时段」组合里只有 2 个（墨黑 dusk / night）发生变化**，其余 14 个逐值不变。

## 取舍与被否方案

1. **否决「拍一个固定地板值（如 1.5:1）」**：那会让墨黑主题夜间（1.16 基准）和纸白主题一起被推亮，破坏「夜晚更沉」的氛围，也会改动浅色主题。用「标准光照对比度」作地板是自洽的。
2. **否决「干脆关掉夜间暗化」**：环境光是设置项 `enableAmbientLighting` 的核心体验（晨曦/正午/黄昏/夜灯），关掉等于砍功能。
3. **否决「给自定义彩色积木也做地板」**：`deriveShadingForColor()` 是从积木自身颜色纯函数派生的，**根本不经过环境光**（也就是彩色建筑在夜间本来就不会变暗）。给它加地板属于另一个视觉决策，且会改变所有彩色建筑在全部主题下的观感 —— 记为后续独立条目。

## 影响面

- 代码：`iso.ts`（新增约 45 行工具 + `applyAmbientLighting` 增加 `bg` 参数、导出以便单测；`paletteFromDocument` 传入 `--bg`）。
- 用户可见：**仅墨黑主题 × 黄昏/夜幕**下，未着色（灰色）积木的背光面比之前亮一档，轮廓重新可辨；其余 14 种组合完全不变。
- 性能：`floorContrast` 每次调色板重建时最多跑 32 次 HSL 换算，而调色板本身有 memo 缓存，无热路径成本。
