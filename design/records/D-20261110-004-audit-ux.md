## 2. 条目详述

### U1 墨黑主题 + 夜间环境光把积木右脸压到 1.03:1（10-03 修复被环境光回归）
- **现象与证据**：`theme.css:53-68` 墨黑主题 `--block-right:#1c1c1c`、`--bg:#0a0a0a`（对比 1.16:1）；`iso.ts:982-990` 夜间环境光对右脸再做 `adjustLightness(right, 0.55)` → 实际渲染 `#0f0f0f`，对 `#0a0a0a` 仅 **1.03:1**（本轮实算）。夜间左脸 `#212121`=1.23:1、顶面 `#3b3b3b`=1.77:1。实测截图：`02-build-light-night-1100x760.png`、`03-build-dark-night-1100x760.png`（对比 `04-build-dark-noon-1100x760.png`：夜景与正午几乎不可区分，块体全靠描边勾形）。触发条件即真实默认值：`enableAmbientLighting !== false`（`BuildScene.tsx:230`）默认开，`getTimePeriod()` 10–16 点外都算 dawn/dusk/night（`iso.ts:956-961`）。
- **根因**：2026-10-03 修「墨黑黑上黑」只调了令牌基色（`--block-right` #0f0f0f→#1c1c1c），没有把环境光的亮度乘法纳入同一约束；夜间 0.55 倍又把修复抹掉，且令牌没有「环境光后最低对比」的下限保护。
- **影响**：墨黑主题用户在 19:00–次日 10:00 的 15 小时里，建造页/展台/落块弹窗的 2.5D 体积感基本消失，只剩 1px 描边；这是产品最强的视觉资产在最高频时段失效。
- **方案**：给「环境光后」结果加对比度地板。`iso.ts:963-996` 的 `applyAmbientLighting` 末尾统一钳制：对 `top/left/right/ghost` 逐色计算与 `p` 背景（新增 `isoBg` 字段由 `--bg` 传入）的 WCAG 对比，低于下限则按比例提亮回下限（深色主题 `right >= 2.2:1`、`left >= 2.6:1`；浅色主题 `top <= 1.0` 方向不做）。草图：
  ```ts
  // iso.ts
  function liftToContrast(fg: string, bg: string, min: number): string {
    let c = fg
    for (let i = 0; i < 24 && contrastRatio(c, bg) < min; i++) c = adjustLightness(c, 1.06)
    return c
  }
  case 'night':
    return { ...lifted, right: liftToContrast(adjustLightness(p.right, 0.55), p.bg, 2.2) }
  ```
  同时把 `enableAmbientLighting` 的默认值从 true 改为 false（或夜间档只在浅色主题启用），把「环境光」降级为可选效果而不是默认破坏可读性。
- **验收**：新增 `iso.test.ts` 用例「dark + night：`contrast(right, bg) >= 2.2` 且 `contrast(left,bg) >= 2.6`」；四主题 × dawn/noon/dusk/night 12 张截图走查（保存到 `.tmp-audit-ux/accept/uv1-*`）。
- **工作量**：S（0.5d 内）
- **依赖**：与 C1 动效令牌无关，可独立先做；改动后需 `npm test`（`iso.test.ts`、`touchGesture.test.ts` canvas mock）。

### U2 全仓缺失 prefers-reduced-motion
- **现象与证据**：`grep -rn "prefers-reduced-motion" src/` = **0 处**（全仓）。实测：`agent-browser set media light reduced-motion` 后 `matchMedia('(prefers-reduced-motion: reduce)').matches === true`，但 `.dialog` 的 computed 仍是 `animation: pop-in 0.22s cubic-bezier(0.16,1,0.3,1)`（截图 `13-settings-reducedmotion-still-animates.png`）。画布侧同样无条件：`BuildScene.tsx:41 DROP_MS = 1350`、`:58-83 jelly/cascade`、`:340-345` 逐帧 rAF；`Build.tsx:311-345` 落成仪式 36 粒 Confetti（`animation: confetti-fall 1.4~2.6s`）；`ui.css:852 float-up-fade 1.1s`、`:1216/1264 pop-in`、`:1269 habit-focus-pulse 1.2s ×2`。而 `design/README.md` A5 原文要求「所有动画必须尊重 `prefers-reduced-motion`」。
- **根因**：动效分散在 CSS keyframes、内联 style、Canvas rAF 三层，没有任何一层读取该媒体查询；无动效令牌（C1）导致无法一次性收敛。
- **影响**：前庭功能障碍/晕动症用户无法关闭 1.35s 的整屏落块与 2.6s 粒子；这是 WCAG 2.3.3（Animation from Interactions, AAA）与系统性体验缺陷。
- **方案**：三层同改。① `theme.css` 末尾加全局降级：`@media (prefers-reduced-motion: reduce){ *,*::before,*::after{ animation-duration:.01ms !important; animation-iteration-count:1 !important; transition-duration:.01ms !important; } .checkin-float-pill,.habit-focus-flash{animation:none !important} }`。② 新增 `src/platform/useReducedMotion.ts`（`matchMedia + change` 订阅），`BuildScene` 在 reduced 时把 `DROP_MS` 设 0、跳过 `jelly/cascade`（保留 120ms 静态高亮）；`Build.tsx` 在 reduced 时不渲染 `<Confetti/>`。③ `BlockDropModal` reduced 时不自动关闭、直接显示落地态。
- **验收**：`useReducedMotion.test.ts`（mock matchMedia true/false 两例）；CDP 手动：`set media light reduced-motion` 后打卡，`document.getAnimations()` 为空、落块在 1 帧内完成、Confetti 不存在。
- **工作量**：M
- **依赖**：与 C1 同批做最省（令牌 + 媒体查询 + canvas 读取三件套）；可先做 CSS 部分（S）止血。

### U3 键盘焦点不可见
- **现象与证据**：`grep -rn ":focus-visible" src/` = **0 处**；仅有的 focus 规则是输入框 `border-color: var(--ink)`（`ui.css:289-292`、`:896-899`、`:963-966`）。实测（light 主题、1100×760）：把焦点放到激活的桌面 tab 后 `computed outline = "rgb(16,16,16) auto 1px"`，而该按钮 `background = rgb(10,10,10)`（`ui.css:89-93`）→ 焦点圈对比 **1.06:1**，肉眼完全不可见（截图 `12-today-light-focus-probe.png`）。同类黑底控件：`.btn.primary`（`ui.css:126-132`）、`.seg button.active`（`ui.css:313-316`）、`.day-check.ready`（`:678-682`）、`.tabbar button.active`。另外 `.footer` 按钮在 `.dialog{overflow:hidden}` 内滚动时默认 outline 也可能被裁。
- **根因**：从 2026-08 的设计体系开始就没有定义焦点态；所有「变黑」都用背景色表达层级，恰好把 UA 默认的深色 outline 吞掉。
- **影响**：键盘/开关控制用户无法知道自己停在哪，等于键盘全流程不可用（WCAG 2.4.7 Focus Visible, A 级失败）。
- **方案**：在 `theme.css` 增加唯一焦点令牌与全局规则，颜色只允许 ink/accent 二选一（不引入新色相）：
  ```css
  /* theme.css */
  :root { --focus-ring: var(--ink); }
  :root[data-theme='dark'] { --focus-ring: var(--accent); } /* 深色底用琥珀，1 个点缀色不外扩 */
  :focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; border-radius: inherit; }
  .btn.primary:focus-visible, .tabbar button.active:focus-visible,
  .day-check.ready:focus-visible, .seg button.active:focus-visible { outline-color: var(--accent); }
  .dialog-footer :focus-visible, .dialog-body :focus-visible { outline-offset: 0; }
  ```
  同时给 `.card-action`/`.icon-btn` 的 `:focus-visible` 加 `background: color-mix(in srgb, var(--ink) 12%, transparent)` 做第二重指示（黑底场景靠描边不够）。
- **验收**：CDP 脚本遍历 `document.querySelectorAll('button, a, input, select, textarea, [tabindex]')` 逐个 focus，断言 `getComputedStyle(el).outlineStyle !== 'none'` 且 `contrast(outlineColor, 最近不透明祖先背景) >= 3`；截图人工抽检 light/dark 两主题。
- **工作量**：S
- **依赖**：无。

### U4 文本/图标对比度系统性不达标

  证据点位：Fog 主题 `.day-check.done{background:var(--progress-green);color:var(--accent-ink)}`（`ui.css:689-694`）在 fog 下 = 白字 `#10b981` 2.54:1。
- **根因**：令牌只按「色相/明度观感」选值，没有按对比度验收；且把 accent 同时当「大面积填充色」（可，1.85 也够用）与「小字/细线图标色」（不可）两种用途共用同一个 `--accent`。
- **影响**：浅色主题最关键的「已完成」状态文字、琥珀强调文字、错误提示、fog 主题几乎所有状态色都低于 WCAG AA；低视力/强光环境下读不清，且「琥珀＝奖励」的信号在浅色底上反而最弱（1.85）。
- **方案**：拆「填充色」与「文字色」两枚令牌，不改观感主调：

### U7 建造页取景按「整蓝图 bbox」：开荒期模型只占画面 ~30–45%
- **现象与证据**：`BuildScene.tsx:566-604` 的 `sceneBounds()` 遍历的是 `stateRef.current.blueprint.blocks`（**整张蓝图**，含尚未放置的高层块），`fitView()`（:617-634）用该 bbox 求 scale 并整体下移 6%。真实数据 53/190 块时：1100×760 窗口下建筑只占横向约 45%、纵向约 63%，画面上半部约 290px 纯空白（截图 `02-build-light-night-1100x760.png`）；820×620 小窗下 canvas 仅 413px 高，建筑缩到 ~220px，可辨识度更低（`11-build-dark-820x620.png`）。
- **根因**：取景要「地基虚线永远完整可见」，于是用蓝图全集兜底，牺牲了「看得见的积累」这个第一隐喻；且未随 placedCount 做进度驱动的取景。
- **影响**：开荒期（前 100 天）建造页信息密度极低，奖励回路最需要「看见成长」的阶段反而最空；小窗/半屏使用时积木细节（凸点、三面着色）不可辨。
- **方案**：改为「已放置块 ∪ 地基脚印」取景，并对缩放做进度插值：
  ```ts
  // BuildScene.tsx sceneBounds()
  const placed = cubes0.slice(0, stateRef.current.placedCount)   // 已放置
  const zMax = Math.max(0, ...placed.map((b) => b.z))            // 当前最高层
  // xs/ys 用 placed 的块 + 蓝图地基四角；高度只算到 zMax
  // fitView 中：
  const groundScale = fit(placedBounds)
  const fullScale = viewRef.current.scale           // 保留用户手动缩放
  const t = placedCount / total                     // 0→1
  viewRef.current = { ...fit(placedBounds), scale: Math.min(fullScale, groundScale / (0.55 + 0.45*t)) }
  ```
  简化版（更安全）：直接以「已放置块 bbox + 地基四角 + 1 格余量」求 sceneBounds，placedCount===0 时退回蓝图地基（不含高层）。并在 `placedCount` 变化且用户未手动缩放（`interactedRef.current===false`）时重新 fitView。
- **验收**：`BuildScene` 现有测试 + 手测 0/10/53/190 块四档取景；截图对比建筑占画幅比例（目标：placed>0 时横向占比 ≥ 60%）。
- **工作量**：S
- **依赖**：与 ART.md §1「自动取景」条目需同步更新（它目前把 617-634 描述为既有规范）。

### C1 动效数值无令牌：17 档时长 / 7 种缓动 / 三处各写一套
- **现象与证据**：全仓 CSS `transition/animation` 与内联 transition 的真实时长共 **17 个不同值**：`0.08/0.1/0.12/0.14/0.15/0.16/0.18/0.2/0.22/0.24/0.28/0.3/0.32/0.4/0.5/1.1/1.2s`（`ui.css` 内 21 条 transition + 10 条 animation，`BottomSheet.tsx:133`、`BottomTabBar.tsx:140/149/170`、`App.tsx` 等内联另计）；缓动共 7 种，其中 `cubic-bezier(0.16,1,0.3,1)` 用了 25 次、`cubic-bezier(0.34,{1.2,1.3,1.4,1.5},0.64,1)` 四种「果冻」参数并存（`ui.css:387/1216`、`:788`、`:1171`、`HabitRow.tsx:303`、`ui.css:133`）。画布侧又是另一套：`DROP_MS 1350`、`BLOCK_T 640`、`easeInCubic`（`BuildScene.tsx:41-52`）。`design/AESTHETIC.md` §7.5 已把它列为设计债；`design/ART.md` §6 只做了「记录」没有「收敛」。
- **根因**：动效在三个技术层（CSS/内联/Canvas）各自实现，没有令牌层。

  ```css
  :root {
    --dur-1: 0.12s; /* 按压/微反馈 */
    --dur-2: 0.18s; /* 悬停/颜色 */
    --dur-3: 0.24s; /* 弹窗进出 */
    --dur-4: 0.32s; /* 抽屉/展开 */
    --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
    --ease-jelly: cubic-bezier(0.34, 1.3, 0.64, 1);
  }
  ```
  在 `iso.ts` 导出同源常量 `MOTION = { drop: 900, block: 520, easeInCubic }`（数值按 A5「≤500ms 等待」压缩，见 U15），`BuildScene` 与 CSS 用同一组语义名。落地顺序：先加令牌 → 机械替换 CSS（可脚本批量）→ 再改画布常量。
- **验收**：`grep -rE "transition: [^;]*[0-9]\.[0-9]+s|animation:.*[0-9]\.[0-9]+s" src/components/ui.css` 只剩令牌变量引用；人工抽检 8 处高频交互无观感突变。

- **依赖**：U2 依赖它的时长语义；U15 复用 `--dur-4`。

### U15 落块弹窗 3.6s 自动关闭 + 1350ms 动画，无快速连打模式
- **现象与证据**：`BlockDropModal.tsx:64-67` 落地后 `setTimeout(triggerClose, 3600)`（仅在输入框 focus/输入/选心情/点星标时取消，`:69-79、:237-241`）；`triggerClose` 自身再等 240ms（`:53-55`）。动画链：`BuildScene.tsx:41 DROP_MS=1350`（+ 落地回调）→ 抽屉展开 `ui.css:909 max-height .32s`。即每次打卡后至少 1.35s 不可交互的整屏遮罩，用户不操作则 3.6s 后自动消失；连续打 6 个习惯 = 6 次全屏遮挡。A5 原文「禁止超过 500ms 的等待动画」。

- **验收**：手测连续打 3 个习惯的节奏；`BlockDropModal.test`（若无则新增）断言「自动关闭定时器在交互后不再触发」。

- **依赖**：C1（`--dur-4`）、U2（reduced 模式）。

## 3. 本轮明确不建议做

1. **重做视觉语言 / 引入第二种立体或彩色主题**：A1–A7 之外的方案一律不做；本轮所有建议都在现有令牌与黑白纪律内。（理由：2026-08 以来三次评审都确认积木等距渲染是产品最强资产，改视觉语言风险极高。）
2. **为热图增加「按月/按年」等更多视图**：当前问题是信息密度与键盘可达（U12），不是视图不够；加视图会稀释「时间形状」的叙事。
3. **引入第三方图表/UI 库解决对比度与菜单问题**：AGENTS.md 硬约束 2 禁止；且现有问题都是令牌/样式级改动。
4. **把落块仪式整体关掉/加速到 200ms**：仪式是核心隐喻（AESTHETIC §2.2），只做「可被 reduced-motion / 快速连打降级」（U2/U15），不做默认削减。
5. **为所有弹窗加自定义过渡库（framer-motion 等）**：C1 的令牌 + 现有 CSS keyframes 已足够；引库会带来新依赖与新动效语言。
