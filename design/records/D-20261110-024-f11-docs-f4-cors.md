### F4：同步失败把「跨域被拦」报成「网络错误」
`webdav.ts` 的 4 处 `fetch` catch 一律 `throw new WebDavError('network', ...)`。而浏览器/WebView 里 CORS 被拦的**典型表现就是 `fetch` 抛 `TypeError: Failed to fetch`** —— 用户会去查网络、查密码、查服务器地址，永远查不到真正原因。

## 设计决定

### 1. 新增 `cors` 错误分类（不新增依赖）
```ts
function isLikelyCors(err: unknown): boolean {
  if (!(err instanceof TypeError)) return false
  const msg = String(err.message ?? '')
  return /failed to fetch|load failed|networkerror|network request failed/i.test(msg) || msg === ''
}
```
4 处 catch（GET / PROPFIND / PUT / MKCOL）统一改为：先判 CORS → `WebDavError('cors')`，否则 `'network'`。

### 2. 给用户可执行的提示
新增 `syncErrors.cors` 文案：说明「标准 WebDAV 服务器默认不返回 CORS 头，桌面 WebView 里的请求同样会被拦下」，并给出**当前可用的替代路径**：先用「导出 / 导入 JSON」在两台设备间搬运数据。

### 3. README 校准 + 新增「已知限制」
- 修正 pages 目录树（补展台页）；
- WebDAV 条目补上 CORS 限制与失败时的提示行为；
- 新增「已知限制」章节：WebDAV 跨域、无自动更新、12 座蓝图 1385 块的内容上限、提醒依赖进程存活；
- 特性清单补上本轮已落地的「备份与恢复」「首启引导」。

## 取舍与被否方案

1. **本轮没有真正修好 WebDAV**：唯一正解是引入 `tauri-plugin-http`（Rust + JS 两个包），属**新增依赖**，AGENTS §4 要求先问；已把它留给人类决策，本轮先把「误报」和「文档撒谎」两件事解决。
2. **否决「把 cors 合进 network，只改文案」**：两个原因的处置完全不同（跨域要改服务器/走桌面通道；断网要检查网络），合并会让日志与按钮行为都失去意义。
3. **否决「在 WebView 里绕过 CORS（改 User-Agent / 关 webview 安全策略）」**：那是在产品里开后门，且 Tauri 也不建议。
