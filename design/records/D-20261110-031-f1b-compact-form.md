## 背景与问题

审计 F1 的后半条：新建习惯表单**最多 14 个字段平铺**（类型 / 名称 / 频率 / 时段 / 提醒 / 目标时长 / 计数目标 / 单位 / 步进 / 分类 / 备注 …）。用户只想「加一个每天喝水的习惯」，却要先面对一屏与自己无关的配置 —— 首启路径的第一个动作就卡住了。

## 设计决定

### 1. 首屏只留「类型 / 名称 / 频率（+ 目标）」
把四组**纯选填**项（时段、到点提醒、分类、备注）折叠进一个开关：
```
更多设置（时段 / 提醒 / 分类 / 备注）  ⌄
```
按钮用 `btn ghost` + `aria-expanded` + 箭头旋转（`--dur-xs` / `--ease-default` 令牌），与设置面板的折叠交互保持一致。

### 2. 必填字段**绝不折叠**
第一版把「目标时长 / 计数目标」也包进了折叠块，随即发现一个问题：切到「专注计时」时**必填的目标时长被藏起来了**，用户会以为没法保存。
因此折叠块被拆成两段：
- 折叠：时段、到点提醒 →（必填目标字段常显）→ 分类、备注 ← 折叠；
- 实测：切到「专注计时」后，未展开「更多设置」也能看到「目标时长」标签。

### 3. 编辑已有习惯时自动展开
若被编辑的习惯已填过任选填项（`period !== 'any'` / `reminder` / `category` / `note`），打开即自动展开 —— 避免「看不见但其实有值」的困惑（与 A6 数据诚实一致）。

## 取舍与被否方案

1. **否决「做成多步向导」**：习惯创建只需要 2–3 个决策，向导会把它拆成 3 屏，反而更慢。
2. **否决「把选填项彻底移除」**：它们对进阶用户有价值（时段分组、提醒、分类筛选）。
3. **否决「全部折叠但保存时校验失败再提示」**：隐藏必填字段再让用户找错，是最糟的交互（第一版已踩到，见上）。

## 影响面

- 代码：`HabitDialog.tsx`（+1 个 state、+1 个折叠开关、两段条件包裹）、i18n 两种语言各 +2 键。
- 用户可见：**新建习惯首屏从「一屏 11 项」变成「4 项 + 一个折叠开关」**；已填选填项的编辑场景自动展开，行为不变。

### 浏览器实测（`npm run dev` + agent-browser）
| 状态 | 表单标签 |
