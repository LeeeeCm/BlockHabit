## 背景与问题

v1 桌宠只有一种带双脚的小兽，右键直接隐藏，没有设置入口，也没有和打卡数据发生关系；用户提出：

- 形象重新优化，不要双脚：可以是「一块会跳的积木」，也可以是「积木机器人」；
- 右键桌宠要有桌宠设置，可自定义；
- 桌宠要和打卡等功能联动；
- 后续可在建造内容里增加桌宠模型，建好后在桌面使用，并注意尺寸。

## 设计决定

- **两种形象**：`block`（单块积木，脸在积木上，无脚，走路用弹跳）与 `robot`（头 / 身体 / 双臂 / 双腿，走路迈腿）；都由 `drawCube` 堆成，不引入贴图。
- **自定义**：设置 → 桌面宠物 提供开关、大小（小/中/大，角色缩放 0.85/1/1.15）、形象（积木 / 机器人）、是否自主走动；机器人完成 **1 座建筑**后解锁（`isPetSkinUnlocked`，后续可扩展为更多模型注册表）。
- **右键**：不再隐藏，改为唤起主窗并打开设置里的桌宠分组（`pet_open_settings` + `open-pet-settings` 事件）；隐藏通过设置开关完成。
- **联动**：主窗通过 Tauri 事件 `pet-config` 同步 `{size, skin, roam, done, total, completed}`。今日完成数增加时，桌宠跳一下并显示 2.6 秒的「完成数/总数」气泡；全完成时同样触发。主窗变更设置/打卡后即时重发；开启后 600ms 补发一次，避免 pet 窗口晚挂载错过。
- **窗口**：仍为 160×180 透明置顶窗；尺寸只缩放角色，不改变窗口，避免再次引入多档窗口。

## 取舍与被否方案

- 否掉「保留 v1 带脚小兽 + 另做机器人」：用户明确不要双脚，积木形态需要重画。
- 否掉「右键弹独立宠物菜单窗」：会新增一个透明窗和跨窗口设置同步；直接打开设置更简单，也能展示全部自定义。
- 否掉「开放任意蓝图模型当桌宠」：模型尺寸/朝向/性能都不可控；先以两种程序化形象 + 完成建筑解锁规则打底。
- 否掉「打卡时自动撒花/说话」：只做一个短气泡和跳跃，避免宠物打断工作。

## 影响面

- 新增 `PetSettingsGroup`；设置分组合并（见 D-093）；`petSize/petSkin/petRoam` 进入设置与存档 sanitize。
- `petRenderer` 支持两种形象；`PetWindow` 增加事件监听、气泡和右键设置。
- Rust 新增 `pet_open_settings`，移除 `pet_request_hide`；capabilities 增加 `core:event:allow-emit-to`。
- 新增 `isPetSkinUnlocked` / `petSizeScale` 单测。

## 验收标准

1. 积木形象无脚、会跳；机器人有头/身体/双臂/双腿，会迈步。
2. 设置可切换大小、形象、自主走动；机器人未完成建筑时禁用并说明。
3. 右键桌宠打开主窗设置并定位到桌宠分组。
4. 完成一次打卡后桌宠跳跃并出现 `done/total` 气泡（2.6s 内）。
5. `tsc`、`vitest`、`cargo check`、`design:check` 通过；桌面端人工验收。
