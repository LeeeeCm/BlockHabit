## 背景与问题

审计 D9（P2）两条：

1. **彩色 emoji 混进严格黑白的界面**：`ReminderDialog` 与今日页提醒横幅里直接写死 `🧱`；9 条应用内文案（打卡成功、落成、镌刻、导出提示）以 `✨ 🎉 🧱 🏛️ 📋` 收尾。A1 说「黑白灰为骨、唯一琥珀点缀」，而 emoji 一条就能带进三四种色相。
2. **全屏背景毛玻璃三套参数**：`.overlay` 用 `blur(14px) saturate(180%)`、`.drop-overlay` 用 `blur(12px) saturate(130%)`、`.brick-inspect-popover` 用 `blur(14px)` 无饱和。同类效果三种数值，且 `saturate(180%)` 与「黑白」公理方向相反（它会**放大**背景里仅有的彩色）。

## 设计决定

### 1. 模糊收敛为单一代币
`theme.css` 新增 `--backdrop-filter: blur(14px) saturate(120%)`，三处全部改用它（含 `-webkit-` 前缀）。

### 2. `🧱` 换成图标库里的积木线稿
用已有的 `IconMoodHard`（16px 网格、圆头线条、`currentColor`）替换两处字面 emoji —— 它本来就是「替代 Emoji 🧱」而画的，语义完全对应。颜色取 `--ink-2`，随主题。

### 3. 9 条文案去掉 emoji
`subtitlePlaced`（✨）、`completedBlueprint`（🎉）、`startBody`（🧱）、`toastComplete`（🎉）、`allDone`（✨）、`tooltipDone`（✨）、`engravedToast`（✨）、`foundationSavedToast`（🏛️）、`exportSuccessToast`（📋）—— 中英各一套共 18 处。**只删符号，不改文字。**

## 取舍与被否方案

1. **保留 8 处注释里的 emoji**（都在 `Icons.tsx` 的「替代彩色 Emoji 💡」注释里）：那是**说明被替代物**的文档，删掉反而看不出这些线稿图标的来历。
2. **保留导出 Markdown 里的 `⭐`**（`Stats.tsx` 手账导出）：那是**用户拿走的文档**里的评级符号，不是界面 chrome；markdown 里用符号比用文字更省空间。
3. **否决「把 saturate 彻底去掉（100%）」**：`120%` 让透过模糊的界面保持一点温度，同时远低于原来的 180%；100% 会让弹窗背景显得发灰。这是审美取舍，写在记录里以便日后调整。
4. **否决「保留 emoji 作为情绪表达」**：本项目已有一条明确做法——所有「情绪」都由线稿图标（`IconMoodEnergetic/Hard/Spark/Calm`）+ 文案承担（见 `design/VOICE.md`），emoji 只在早期版本出现过。

## 影响面

- 代码：`theme.css` +1 令牌；`ui.css` 3 处改引用；`ReminderDialog.tsx` / `Today.tsx` 换图标；i18n 18 处文案。
- 用户可见：**实测像素零变化**（见验收）—— 因为界面本身是灰阶，`saturate(180%→120%)` 在灰阶内容上不产生任何通道差异；emoji 出现的两处（提醒横幅/列表）在默认测试状态下不可见，图标替换在编译期完成。
- 长期：三套模糊参数变一套，后续调档只需改一个变量。

## 验收标准

### 视觉回归（决定性证据）
设置弹窗（`.overlay` 生效）与今日页在改动前后各截一张，`sharp` 逐像素比对（阈值 ±2/通道）：
| 界面 | 变化像素 / 总像素 |
| --- | --- |
| 设置弹窗（背景模糊 + 饱和） | **0 / 790,000** |
| 今日页 | **0 / 790,000** |

结论：`saturate(180%)` 在灰阶界面上**本来就没有可见效果** —— 这是一处纯「参数噪音」，收敛为零风险。

- `npx tsc --noEmit` 0 错误；`npm test` **59 文件 / 474 用例全绿**。
