## 背景与问题

两条同属「本地优先产品的支持链路」：

- **F9（P3）**：应用没有任何诊断手段。用户报「卡/崩了」时，维护者手里只有一句描述；而 A4 建立的崩溃日志存在 localStorage 里，用户看不到也导不出。
- **F7（P2）**：提醒只在进程存活时生效，而「开机自启」默认关闭且**没有任何提示**。用户以为设了提醒就会收到，结果关掉应用后一个提醒都没有——这是最典型的「功能静默失效」。

## 设计决定

### 1. F9：`src/platform/diagnostics.ts`（纯本地，零网络）
| 组成 | 内容 |
| --- | --- |
| 基础信息 | 应用版本、UA、语言、平台、生成时间（复用 A4 已有的 `buildDiagnosticsText`） |
| 崩溃日志 | 最近 30 条（时间/类型/消息/堆栈） |
| **数据体量** | 习惯数（含归档）、打卡数、积木数、落成蓝图数、全勤领取数、修复积木库存、奠基石数、提醒日志条数、主题/语言、**存档字符数**、**存储后端**（tauri / localStorage / unavailable） |
| **帧率采样** | 1.2 秒 rAF 采样 → `fps` + 最慢一帧毫秒；无 rAF / 减少动态时明确写「未采样」而不是留空 |

导出仍是「Blob + 临时 `<a>`」的本地方案（不引入 Tauri 插件、不发请求），文件名带时间戳。入口放在设置 → **实验室** 组底部，旁边写明「只在本机生成，不会上传」。

### 2. F7：自检提示（不新增开关、不弹强制引导）
设置 → 系统组内，当 **提醒已开启 且 开机自启为关闭** 时，展示一行说明：
> 提醒只在应用运行中生效。若希望关掉应用也能到点提醒，请开启「开机自启」并允许它常驻后台。

选「就地提示」而不是「首启弹窗」的理由：弹窗会打断首次使用路径（F1 刚整理过），而用户只有在真正配置提醒时才需要这条信息。

## 取舍与被否方案

1. **否决「做远端上报/遥测」**：AGENTS §3 与 A7 明令本地优先、无遥测；诊断包是**用户主动导出**的文件，用户能先自己看一遍。
2. **否决「把诊断包做成自动发送」**：同上，且自动发送会让「本地优先」承诺变得可疑。
3. **否决「帧率采样常驻后台」**：会持续消耗性能，反而制造它要诊断的问题；改为**导出瞬间采样 1.2 秒**。
4. **否决「F7 用一次性弹窗」**：见上。

## 影响面

- 代码：新增 `diagnostics.ts`（约 190 行）+ 6 例单测；`SettingsDialog` 增加按钮与自检提示；i18n 两种语言各 +6 键。
- 用户可见：设置 → 实验室里多一个「导出诊断包」按钮；设置 → 系统里在特定条件下多一行提示。**不动任何既有控件的样式与布局顺序**。

## 验收标准

### 自动化（已通过）
- `src/platform/diagnostics.test.ts` 6 例：数据体量计数（含归档、空状态）、存储后端识别、报告含三大区块、未采样时的显式说明、报告为纯文本且不含 URL。
- 全量：`npx tsc --noEmit` 0 错误；`npm test` **62 文件 / 505 用例全绿**。

### 端到端实测（浏览器内拦截 Blob 验证真实导出）
把 `URL.createObjectURL` 与 `anchor.click` 临时替换为捕获实现，点击「导出诊断包」后读取 Blob：
- 产物 **853 字符**；
- 含 `BlockHabit Diagnostics`（基础信息）、`Data summary (local only)`（存储后端 localStorage / schema 2 / 存档 ~670 字符 / 各层计数）、`Render sampling`（帧率）、`Crash log`；
- 关键隐私断言成立：**文本中不含任何 http(s) 链接**，且末尾写明「No data was uploaded」。

### 待人工验收（桌面端）
设置 → 系统：开启提醒、关闭自启 → 应出现自检提示；开启自启后消失。
