## 0. 一页结论

### 0.1 一句话定位

> **BlockHabit 是桌面陪伴型习惯应用：把每天坚持的 10 秒，变成桌面上看得见、拿得走、拼得完的物理积累。**

它不是「更好的打卡清单」，也不是「游戏化 RPG」，更不是「效率待办」。它同时占住三件竞品最多只能占两件的事：

1. **桌面常驻**（不是手机 App，也不只是网页）；
2. **物理积累**（积木与建筑是唯一奖励，不用虚拟货币、不做等级）；
3. **本地优先**（无账号、无云、数据是用户自己的文件）。

### 0.2 三个判断

1. **习惯赛道的主战场在手机，桌面是空位。** 本次核查的 15 个产品里，真正以 Windows/macOS 桌面为主形态的只有 Focus Bear（专注/阻断）与 NekoTrak（桌面宠物+时间追踪）；TickTick、Microsoft To Do、Apple Reminders 的桌面端是同步端/系统端而非主形态，其余全部是移动或 Web 优先。桌面常驻 × 长期可视化积累这个组合，市面上没有直接对手。
2. **「看得见的积累物」是最强留存器，但主流选择的是虚拟物。** Forest 的树、Finch 的宠物都已经验证「每天照顾一个东西」的威力（Finch 美区 App Store 4.95 分 / 77 万+评分，可验证）；BlockHabit 的建筑是**第三种积累物**：不属于宠物、不属于游戏资产，而是一件会留在家里的东西。这是差异化，也是必须保护的核心资产。
3. **订阅化把「买断 + 本地文件」推成反向卖点，但只有补齐可信分发与可迁移数据才成立。** Forest 在 2026 年被媒体记录「买断转订阅、老用户不满」（红星资本局 2026-07-30），Habitica/Finch/Habitify 全部是订阅 + 云账号。BlockHabit 的差异点（本地 JSON、WebDAV 自托管、无账号）是真实的市场缝隙，但它目前还缺两块信任基建：**代码签名与自动更新**（`design/records/D-20261110-048-decisions-and-f4-http.md` 决议「无签名证书暂不接 updater」）。

### 0.3 本轮策略结论（一段话）

**守住三条公理换来的位置，补两处信任缺口，拒绝三件会稀释产品的事。**
守住：等距积木、桌面常驻、本地优先。补：桌面摆件的「每天看见」、数据与内容的「长期故事」。拒绝：社交/排行、游戏化经济、账号与云服务。内容终局（12 座蓝图 1385 块）必须用「纪念/年鉴」收尾，而不是用更多玩法拖延——这是本文件与 `design/records/D-20261110-038-f2-endgame-messaging.md` 一致的判断。

### 1.3 五条横向读数

1. **赛道在从「追踪」转向「陪伴/情绪」。** 纯打卡（Streaks、everyday、Loop）靠极简和低价活着；高评分高粘性的产品（Finch 4.95、Forest 4.79、Streaks 4.81）都在卖「每天照顾一个东西」的感觉。BlockHabit 的建筑已经是「一个东西」，只是目前被藏在建造页里，没有成为每天的情绪对象。
2. **订阅化正在制造反向需求。** Forest 从买断转 Plus 订阅被媒体点名；Habitica/Finch/Habitify/Structured/TickTick/Focus Bear 全部订阅。**买断或捐赠 + 本地数据**是市场上真实存在的空位，但它需要「可信分发」背书（签名、更新、官网），否则用户不敢把十年的数据交给一个 exe。
3. **桌面端不是没人做，是没人把它当「家」做。** Focus Bear 把桌面当「控制台」，NekoTrak 把桌面当「游戏场景」，TickTick 把桌面当「另一个同步端」。没有人把桌面当**展示架/工作台**——而这恰好是等距建筑最擅长的。
4. **系统级基线不可战胜，只能绕开。** Apple Reminders 与 Microsoft To Do 免费、系统级、零安装；任何「提醒/清单/同步」功能都不构成差异化。产品差异必须落在系统做不了的三件事：**独特的视觉资产、桌面陪伴形态、本地文件主权**。
5. **内容经济是 BlockHabit 的独特点，也是它的悬崖。** 任务型产品的内容无限（任务本身），积累型产品的内容有限（12 座蓝图 = 1385 块）。有限性带来仪式感与完成感，也带来「第 191 天之后是什么」的问题。竞品用无限任务掩盖了这个问题，BlockHabit 必须正面回答。

## 2. BlockHabit 的优劣势

> 每条都尽量指到仓库文件或已知限制。判定以 2026-11-10 工作区代码与设计记录为准。

### 2.1 优势（6 条）

1. **等距积木建筑是唯一的「可长期积累的物理资产」。**
   `src/render/isoGeometry.ts` / `isoCube.ts` / `isoColor.ts` / `isoGround.ts` 提供三面着色 + 圆角 + 凸点 + 接触阴影；`src/render/BuildScene.tsx` 负责落块与场景；`src/logic/blueprints/generators.ts` 定义 12 座蓝图共 1385 块。竞品的「可视化」都是当下状态（进度条、日历、宠物），BlockHabit 的是**历史总和**——每块积木都对应一次真实打卡。
2. **桌面原生形态完整，是竞品没有的组合。**
   单实例保护、托盘、关窗收托盘、退出握手（`src-tauri/src/lib.rs`）、开机自启（autostart 插件）、置顶迷你摆件（`src/components/MiniDeskToy.tsx`，260×380 窗口内展示正在建造的 3D 建筑 + 快捷打卡）、自定义托盘菜单（`src/components/TrayMenu.tsx`）。Focus Bear 有桌面但卖「阻断」，NekoTrak 有桌面但卖「时间监控」；只有 BlockHabit 把桌面当展示架。
3. **本地优先与数据主权是真实能力，不只是口号。**
   `src/storage/tauriStorage.ts`（appDataDir JSON、原子写）、`src/storage/adapter.ts`（schema v2 校验/净化）、`src/storage/backups.ts`（应用内备份列表、一键恢复、打开数据目录，见 `D-20261110-022`）、导出/导入 JSON；同步是可选 WebDAV（`src/sync/merge.ts` 墓碑合并），桌面端已走 Tauri 原生 HTTP 绕开 CORS（`src/platform/http.ts`，见 `D-20261110-048`）。
4. **黑白纪律与四主题是长期使用的资产，不是限制。**
   `design/AESTHETIC.md` A1/A4 定义「黑白灰为骨、每主题一枚点缀色」；`src/theme.css` 令牌化到 canvas；`D-20261110-048` 把公理明确为「同一时刻一枚点缀色相」，`D-20261110-049` 用「单环 / 双环」而不是新颜色区分奖励等级。对比 Habitica 的像素彩色与 Finch 的糖果色，BlockHabit 更耐看、更适合每天看十年。
5. **宽容机制（温和风化 + 修复积木 + 全勤）是对「断签焦虑」的差异化回答。**
   `src/logic/streak.ts`（温和风化：昨日偶发断卡进入晨雾休整期）、`src/logic/repairBricks.ts` 与 `src/store/appStore.ts`（月度额度 2 + 连击里程碑，库存上限 4）、`DayClaim` 全勤记录（`src/types.ts`）。Forest 用「树枯死」、Habitica 用「掉 HP」制造损失厌恶；BlockHabit 用「可修复」表达长期主义——这更接近真实习惯的形成。
6. **内容终局是诚实的，不是静默的。**
   `src/logic/blockHints.ts` 的 `all-blueprints-complete` 分支 + `src/pages/Build.tsx` 的常驻完成说明 + `src/pages/Today.tsx` 打卡时的明确告知（`D-20261110-038`）：12 座全部落成后打卡仍记录、但不再掉块，用户知道发生了什么。竞品里没有「内容用完」这回事，所以也没有人处理「用完」的体验——这是 BlockHabit 可以做得比别人更体面的地方。

### 2.2 劣势（8 条）

1. **没有移动构建，缺席最大的入口。**
   `README.md`「平台范围」与 `D-20261110-050` 明确：移动端只是「实验」，无构建目标、不投入开发。习惯应用的主战场在手机；BlockHabit 只能服务「每天会打开电脑的人」。
2. **内容悬崖：1385 块之后没有新故事。**
   `README.md`「已知限制」写明 12 座共 1385 块、全建成后不再掉落；`D-20261110-038` 把「落成后是否自由建造/重铸」列为**待人类决策**。按审计估算，1 个习惯的日常用户约 2 块/天 → 全 12 座约 690 天；3 个习惯约 4 块/天 → 约 347 天。一年左右就会撞上终局。
3. **同步门槛对普通用户过高。**
   需要自备 WebDAV 服务器与凭据（`src/components/SettingsDialog.tsx` 的 WebDAV 面板、`src/sync/webdav.ts`）；桌面端虽已解决 CORS，但浏览器预览仍是标准 `fetch`；与 Finch/Habitify 的「登录即可跨设备」相比，这是可用性差距，也是数据主权路线的必要代价。
4. **提醒依赖进程存活。**
   `README.md` 与 `src/components/ReminderWatcher.tsx` 都说明「应用完全退出后不会提醒」；`D-20261110-030` 已加自检提示，但「开机自启默认关」仍让一部分用户以为提醒失效。
5. **没有代码签名、自动更新与官网渠道。**
   `D-20261110-048` 决议：无签名证书则不接 updater；`README.md` 写明「没有自动更新，安装包需手动下载覆盖安装」；仓库根目录也没有发布页/商店素材。Windows SmartScreen 对未签名安装包的警告会直接吃掉首装转化，也意味着 C1/C2 这类问题无法热修。
6. **首日引导刚补齐，长期动机仍主要靠「内容」而非「关系」。**
   `D-20261110-023`（三步引导 + 首块说明）、`D-20261110-052/053/054/055`（今日简报、模板、页面提示、晚间提醒）正在补；但没有社交/问责（AESTHETIC §5 的自觉选择），对「需要别人监督」的用户天然无解。
7. **体量与性能仍有历史包袱。**
   审计 `D-20261110-005` 记录安装包 11.47/12.54 MB；到 `D-20261110-051` 已降到 NSIS **8.53 MB** / MSI **10.13 MB**（引入原生 HTTP 后反而更小），但相对「极简小工具」仍偏重；渲染三件套曾是 2,528 行热路径（`D-005` C10），`D-20261110-044/045/057` 已拆分并做性能实测。
8. **没有品牌与渠道资产。**
   仓库只有 `README.md` / `CHANGELOG.md` / 设计资产；没有官网、商店详情页文案、截图素材与评测触达（这是发布问题，不是代码问题，但决定了「差异化能否被看见」）。

### 2.3 定位矩阵（相对竞品的错位）

| 应用 | 桌面常驻 | 可视化积累物 | 本机优先 | 游戏化经济 |
|---|---|---|---|---|
| **BlockHabit** | ✅ 托盘 + 置顶摆件 | ✅ 等距建筑（可导出） | ✅ 本地 JSON + 自托管 WebDAV | ❌（明确不做） |
| Finch | ❌（移动） | ✅ 虚拟宠物 | ❌ 云账号 | 轻度（能量/装饰） |
| Forest | ❌（移动） | ✅ 虚拟树 | 部分（应用内记录） | 轻度（金币/树种） |
| NekoTrak | ✅（Windows） | ✅ 像素猫 | 部分（本地，但分享到 Steam/Discord） | ✅（经验/金币/收集） |
| Focus Bear | ✅（桌面 App） | ❌ | ❌ 云账号 | ❌ |
| Loop | ❌ | 部分（热图） | ✅ 全本地、无网络权限 | ❌ |
| Habitica | ❌ | 虚拟角色/装备 | ❌ 云账号 | ✅ |
| Streaks | ❌（Mac 版可运行） | 部分（连击/网格） | 部分（iCloud） | ❌ |
| TickTick / To Do / Reminders | ✅（桌面端） | ❌ | ❌ 云账号 | ❌ |

> 结论：**没有任何竞品同时占住「桌面常驻 + 可视化积累物 + 本机优先 + 非游戏化」。** 这就是 BlockHabit 的位置，也是所有设计取舍的边界条件。

## 3. 差异化与创新建议（10 条）

> 分三档：**A. 现在就能做（≤1 周）**、**B. 需要一轮设计**、**C. 明确不做**。
> 每条都写：做什么 / 为什么是差异化 / 成本 / 风险 / 与 AESTHETIC 公理的关系。
> 成本口径：S（1–2 天）、M（3–5 天）、L（一轮设计 + 实施）。

### A. 现在就能做（≤1 周，4 条）

#### A1. 桌面摆件「三档尺寸 + 置顶开关」：让建筑真的待在桌面上

- **做什么**：把 `src/components/MiniDeskToy.tsx` 的固定 260×380 窗口扩展为三档（例如 220×320 / 260×380 / 320×460），在设置与窗口内提供「置顶 / 取消置顶」开关；尺寸偏好进 `AppSettings`（与 `enableMiniWidget` 同组），窗口几何在 `src/App.tsx` 的 toggleMini 路径统一下发。首次进入迷你模式时给一次说明（复用 `GuideTip`）。
- **为什么差异化**：竞品里没有「把长期积累物放在桌面上每天路过看见」的产品。Focus Bear 的桌面是控制台、NekoTrak 的桌面是游戏场景；BlockHabit 的桌面是**展示架**。这一条把「桌面陪伴」从概念变成每天可见的事实，成本极低。
- **成本**：S–M（窗口几何 + 设置项 + 三处测试回归）。
- **风险**：迷你窗历史上出过「关闭后卡在小窗 / 尺寸锁死」的问题（`D-20261110-019` 已修）；新增尺寸档必须回归 Alt+F4、托盘唤起、多显示器、DPI 缩放四条路径。
- **公理关系**：不冲突。遵守 A2（窗口也是积木容器）、A4（无新增阴影/颜色）、A5（无新动效）；尺寸变化不涉及视觉语言。

#### A2. 「落成年鉴」：给每一座落成的建筑一张可归档的铭牌

- **做什么**：在展台（`src/pages/Showcase.tsx`）与建造页为每座已落成建筑生成一张「年鉴卡」：落成日期（取该蓝图最后一块积木的 `placedAt`，`src/types.ts` 的 `PlacedBlock` 已具备）、总块数、打卡总次数、全勤天数、专注分钟（`CheckIn.actualMinutes`）、奠基石铭言（`foundationNotes`）。复用 `src/components/PolaroidModal.tsx` / `MonthlyPosterModal.tsx` 的画布与导出路径，新增一张「年鉴」版式；年度可另出一张「年度画报」。
- **为什么差异化**：竞品的统计都是「当前状态」（连击、热图、图表），没有把「完成物」做成可收藏的纪念品。BlockHabit 的每座建筑是几个月真实时间的物证，给它一张铭牌，等于把「完成」变成可回看的记忆，而不仅是进度条归零。
- **成本**：S（纯查询 + 画布版式 + i18n + 展台入口）；不需要改数据模型。
- **风险**：画布内文字属于 i18n 例外（`design/VOICE.md` §5 已有先例），需中英双版；导出通道历史上存在「Tauri 端 <a download> 是否真能落盘」的待验证项（审计「待验证」§1），需顺手验证或降级为「复制/另存」。
- **公理关系**：A1（点缀色只用于奖励，铭牌用黑白灰 + 点缀色描边）、A3（等距缩略图复用同一投影）、A6（数字全部来自事实数据，不估算）。

#### A3. WebDAV「服务商预设 + 连接自检」：把数据主权做成能用的功能

- **做什么**：在设置 → 同步面板（`src/components/SettingsDialog.tsx`）加三个「模板」按钮（Nextcloud / 坚果云 / 群晖，仅 URL 模板，不预填凭据），以及一个「测试连接」按钮：分步返回「地址不可达 / 证书错误 / 401 凭据 / 跨域被拦（浏览器预览）/ 目录不可写」，每类给一句人话建议。桌面端复用 `src/platform/http.ts` 的原生 HTTP 通道。
- **为什么差异化**：所有主流竞品都是「登录即同步」，用户没有选择；BlockHabit 的 WebDAV 是「你自己的云」。但当前门槛（自己找 URL、自己判断错误）让这个卖点只对技术用户成立。把门槛降到「选一个服务商、填账号、测试通过」，数据主权才从口号变成产品能力。
- **成本**：S（纯前端表单 + 错误码映射 + i18n；网络层已就绪）。
- **风险**：预设 URL 可能随服务商改版失效，需在文案里写明「请以服务商文档为准」；绝不能把用户凭据发到任何第三方。
- **公理关系**：直接强化 A7；不新增颜色与组件形态（沿用既有输入框与胶囊按钮）。

#### A4. 「一键档案包」：把数字家当打包带走

- **做什么**：设置 → 数据组新增「导出档案包」：一个压缩包/文件夹，包含 `blockhabit.json`、12 座建筑的 PNG 长图（复用 `showcaseLayout` 与场景渲染）、一份人可读的 `README.txt`（版本、导出日期、块数、落成清单）、以及 `sha256` 校验文件。浏览器环境降级为逐个下载。
- **为什么差异化**：Loop 有导出但没有视觉资产，Streaks 只有 iCloud。BlockHabit 的建筑是用户投入几个月换来的东西，应该能像相册一样被打包、备份、传给未来的自己。这是「本地优先」最直观的证据，也是对「你敢把十年数据交给云吗」的正面回答。
- **成本**：S–M（Tauri 侧写目录 + 浏览器降级 + 校验和）。
- **风险**：不引入压缩库（AGENTS：不新增依赖）→ 用「文件夹 + 多个文件」代替 zip；导出大小与路径需在 UI 明示；不联网、不上传。
- **公理关系**：A7 的直接延伸；A6（包内数字全部来自真实数据）。

### B. 需要一轮设计（3 条）

#### B1. 内容供给二期：蓝图「扩展包 / 扩建模式」替代无限玩法

- **做什么**：给终局后的用户两条路（二选一或分期）：
  1. **扩建**：已落成建筑可继续加盖装饰块（重新启用同一蓝图，追加约 20% 块数，视觉上用既有圆角几何与低饱和装饰色）；
  2. **蓝图扩展包**：参数化生成器（`src/logic/blueprints/generators.ts` 已有参数化能力）按月/按季产出新蓝图，黑白灰 + 既有装饰色纪律不变。
- **为什么差异化**：竞品用「无限任务」掩盖内容问题；BlockHabit 的有限内容是仪式感来源，不能靠「更多同质建筑」硬拖。把终局变成「收藏完成的建筑 + 继续扩建自己的作品」，既延寿又不通胀。
- **成本**：M–L（内容设计 + 美术资产 + 蓝图校验 + i18n + 设计记录）。
- **风险**：A1 的点缀色纪律与 ART.md 的「蓝图装饰色是刻意保留的实物隐喻」（`D-20261110-048` 决议 3）之间需要新的取舍；扩建会改变「块数=天数」的直觉，必须同步更新 README 与界面口径（A6）。
- **公理关系**：A2/A3 可兼容；A1 需要一次正式记录与人工批准；A6 要求所有进度表达仍以事实块数为准。

#### B2. 桌面专注陪伴：把「专注习惯」变成桌面上的 25 分钟

- **做什么**：把 `Habit.kind === 'focus'` 与迷你摆件/托盘打通：开始专注时，摆件显示倒计时与「正在为《蓝图》攒一块」；结束后落块动画在摆件里播放一次（不循环）。不做应用监控、不做网站拦截、不读取其他窗口。
- **为什么差异化**：Focus Bear 验证了「桌面 + 专注 + 习惯」可以卖 $9.99/月，但它的卖点是控制（阻断干扰）；BlockHabit 的卖点可以是**奖励**（专注 25 分钟 → 桌面上的建筑多一块）。同一需求，相反的价值观，且不需要系统级监控权限。
- **成本**：M（计时器与提醒/通知协调、窗口状态同步、动画复用）。
- **风险**：与到点提醒、晚间提醒的功能重叠；摆件长时间计时会带来性能负担（`D-20261110-057` 的性能预算需要复核）；不能滑向「专注监控」——那是 A7 与隐私红线的反面。
- **公理关系**：A5（动效克制、仪式只演一次）、A7（不联网、不监控）；不新增颜色。

#### B3. 「建筑即编年史」：以建筑为容器回看每天的随笔与心境

- **做什么**：在建造页/展台点击任意积木，弹出「这一天」：当天的打卡随笔（`CheckIn.note`）、心境（`CheckIn.mood`）、习惯名、专注分钟、是否全勤。把现有「手账长廊」「透视考古」的能力从「按时间列表」升级为「按建筑翻阅」，并在落成时生成一篇「落成编年史」（复用 `MonthlyPosterModal` 的版式语言）。
- **为什么差异化**：竞品的日记与习惯是两套系统（Finch 有 journal，Habitica 有任务）；BlockHabit 的积木天然是「日期 + 事件 + 位置」的三元组，建筑就是一本立体的日记。这是任何竞品都复制不了的结构。
- **成本**：M（查询与索引、弹层 UI、性能；大建筑 190 块下的点击命中与查询要压测）。
- **风险**：`CheckIn` 数据可能稀疏（用户不一定每天写随笔），空态要诚实（A6：没有就显示没有）；渲染层点击命中已有 `BrickInspectPopover.tsx` 可复用，但需确认性能。
- **公理关系**：A3（同一投影）、A6（数据诚实）；不新增色相，随笔高亮沿用 `--accent`。

### C. 明确不做（3 条）

#### C1. 不做社交 / 好友 / 排行榜 / 团队监督

- **做什么（如果做会是什么）**：好友互看进度、连击排行榜、组队打卡、分享到社区。
- **为什么不做**：`design/AESTHETIC.md` §5 第一条明确「不做社交：无好友、无排行榜、无分享到社区（本地导出图片是唯一出口）」。社交必然带来账号与云（违反 A7），并会把「为自己坚持」变成「为别人表演」。Habitica 的社交是重 UI 换来的，Finch 的 Friends 也建立在云账号上——这两条都不是 BlockHabit 能低成本复制的路。
- **成本（如果做）**：M–L（账号、后端、隐私合规、举报与内容安全）。
- **风险（如果做）**：直接摧毁「本地优先、无账号、无遥测」三条禁令，且不可逆。
- **公理关系**：直接违反 A7 与 AESTHETIC §5。

#### C2. 不做虚拟货币 / 等级 / 成就徽章 / 养成宠物

- **做什么（如果做会是什么）**：金币、经验、等级、徽章墙、可喂养的建筑宠物。
- **为什么不做**：AESTHETIC §5 明确「奖励只有积木、建筑与铭文」。`D-20261110-005` 的 C7 已经证明：一旦奖励语义混叠（全勤块与连击块共用 `bonus`），点缀色的稀缺性就被稀释；`D-20261110-049` 用「单环/双环」而不是新颜色修补，说明团队已经在为视觉纪律付代价。再引入虚拟货币，会让积木从「物证」降级为「代币」。
- **成本（如果做）**：L（经济系统 + 数值 + 视觉资产）。
- **风险（如果做）**：奖励通胀、目标漂移、与「物理积累」定位冲突；参考 Habitica 的重机制学习成本。
- **公理关系**：直接违反 AESTHETIC §5 与 A1 的奖励预算。

#### C3. 不做账号体系 / 云同步服务 / 订阅付费墙（本轮）

- **做什么（如果做会是什么）**：注册登录、官方云同步、订阅解锁功能。
- **为什么不做**：`D-20261110-005` 的 P3 结论是「现在不做付费」；账号与云同步会摧毁数据主权卖点，并把单人维护的项目拖进服务器运维、隐私合规与客服成本。商业化的正确顺序是：**签名 + 自动更新 + 备份恢复先到位，再考虑买断或捐赠**（`D-20261110-048` 已明确无签名不接 updater）。
- **成本（如果做）**：L（后端、账号、支付、税务）。
- **风险（如果做）**：破坏 A7；把「可带走的数据」变成「被托管的数据」。
- **公理关系**：违反 A7；与 `design/AESTHETIC.md` §5「不做必须联网的主路径」一致。

### 3.4 优先级排序（收益 / 成本 / 依赖）

| 优先级 | 建议 | 收益 | 成本 | 依赖 / 前置 |
|---|---|---|---|---|
| 1 | A1 摆件三档 + 置顶 | 高（每天可见的差异化） | S–M | 无；回归 `D-20261110-019` 的窗口行为 |
| 2 | A3 WebDAV 预设 + 自检 | 高（把数据主权变成可用功能） | S | 无（原生 HTTP 已就绪） |
| 3 | A4 一键档案包 | 中高（信任与迁移） | S–M | 审计「待验证」§1 的导出通道 |
| 4 | A2 落成年鉴 | 中高（把完成物变成记忆） | S | 无（数据可取） |
| 5 | B2 桌面专注陪伴 | 高（桌面场景的正面对手） | M | 依赖 A1 的窗口形态；性能复核 |
| 6 | B3 建筑即编年史 | 中高（独有叙事结构） | M | 渲染性能与点击命中 |
| 7 | B1 内容供给二期 | 高（长期留存） | M–L | 需要设计记录与人工批准；美术预算 |

> 排序原则：先做「让现有差异被看见、被信任」的低成本项（A 档），再做「扩大差异」的中成本项（B 档）。C 档任何一条都不进排期。

## 5. 结论的前提与风险（写清「什么情况下这些建议会失效」）

1. **一切对外表达的前提是可信分发。** 没有代码签名与自动更新（`D-20261110-048` 决议），「买断 / 捐赠 + 本地数据」的叙事会被 SmartScreen 警告与「版本回不去」抵消；A4/A3 的信任价值也会打折。
2. **数据安全必须先于数据主权宣传。** 备份恢复、损坏备份、打开数据目录已由 `D-20261110-022` 补上；但「十年数据」的承诺还要求导出通道真机验证（审计「待验证」§1）与恢复演练。
3. **桌面单平台是约束，不是缺陷。** `README.md` 明确 Windows 是唯一正式目标；所有「桌面陪伴」建议都应以 Windows 托盘/窗口行为为准，macOS 暂不作为验收面。
4. **内容二期需要人类决策与美术预算。** `D-20261110-038` 把「落成后自由建造/重铸」列为待决策；B1 不是工程能单方面启动的事。
5. **任何新表面都要先写设计记录。** 按 `AGENTS.md` §1 与 `design/README.md`：记录先于代码，公理逐条自检；本文档只是输入，不是批准。
