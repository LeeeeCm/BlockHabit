## 0. 一页结论

**BlockHabit 的差异化不在「打卡做得更好」，而在「把坚持变成一件留在家里的东西」。**

竞品最多同时占住三件事中的两件：**陪伴**（Finch 的宠物）、**积累**（Forest 的树 / 建筑）、**本地**（Loop 的离线）。BlockHabit 同时占三件，并额外拥有一个别人没有的形态——**桌面当展示架**。

因此创新只沿三条线展开，拒绝第四条：

| 线 | 要回答的问题 | 对应创新 |
| --- | --- | --- |
| **每天看见** | 用户为什么会主动打开、会一直开着？ | A1 桌面摆件三档、B2 专注陪伴、打开回路（已做） |
| **长期故事** | 第 191 天之后还有什么？ | A2 落成年鉴、B1 内容二期、B3 建筑编年史 |
| **数据主权** | 凭什么把多年数据交给一个 exe？ | A3 WebDAV 预设与自检、A4 一键档案包 |

**建议节奏**：0.3.0「每天看见它」先做 A1 + A3 + A2；0.4.0「陪伴与带走」做 B2 + A4 + B3；0.5.0「长期故事」再做 B1 内容包与分发前置（签名 / 自动更新）。不先做 B1——内容包在没有可信分发前只是把内容给了现有用户，解决不了「新用户敢不敢装」。

## 1. 战略层

### 1.1 定位与三条护城河

> **桌面陪伴型习惯应用：把每天坚持的 10 秒，变成桌面上看得见、拿得走、拼得完的物理积累。**

1. **物理积累资产**：12 座 1385 块等距积木建筑，是时间的历史总和，不是当下状态。竞品的可视化（宠物、树、热图）都是「现在」，BlockHabit 是「过去所有天的总和」。
2. **桌面常驻形态**：托盘、单实例、关窗收托盘、退出存档握手、开机自启、置顶迷你摆件。竞品把桌面当同步端（TickTick）或控制台（Focus Bear），只有 BlockHabit 把桌面当展示架。
3. **本地数据主权**：无账号、无云、无遥测；JSON 存档 + 备份 + 可选 WebDAV；可导出可恢复。这是订阅疲劳时代真实存在的反向需求，但前提是分发可信（签名 / 更新 / 备份恢复）。

### 1.2 创新原则（任何新功能先过这五条）

1. **只服务三条线**：不能强化「每天看见 / 长期故事 / 数据主权」的功能，不做。
2. **默认离线可用**：网络只允许出现在可选 WebDAV；核心路径断网不降级。
3. **不制造焦虑**：提醒只陈述事实，不做连击羞辱、不做对比排行、不做假数据。
4. **视觉零新色相**：新表面只用 `TOKENS.md` 既有令牌；先补 `SURFACES.md` 再写代码。
5. **每个创新必须有「退出」**：可关闭、可撤销、可导出；不做不可逆的体验。

### 1.3 成功如何衡量（无遥测前提）

遵守 A7，本轮不上报任何数据。因此定义**可本地验证 / 可人工复核**的指标，而不是 DAU/留存：

| 指标 | 目标 | 采集方式 |
| --- | --- | --- |
| 打开应用 → 完成第一次打卡 | ≤ 3 次交互 / ≤ 10 秒 | CDP 录屏 + 手测脚本 |
| 首次建习惯 | ≤ 2 次点击（模板路径） | 浏览器脚本 |
| 页面切换 | 首次 ≤ 30ms，二次 ≤ 15ms | CDP 计时（已建立基线） |
| 冷启动可交互 | ≤ 500ms（安装版目标） | 真机计时 + 本地性能面板 |
| 数据可迁移 | 100% 字段可导出、可恢复 | 档案包 round-trip 测试 |
| 提醒准确性 | 0 误报 / 每天最多一次 | 单测 + 真机 21:00 验证 |
| 内容供给 | ≥ 2 年（当前 693 天） | 蓝图块数 / 用户节奏复算 |

> 如果未来要做留存分析，只允许「用户主动导出的本地诊断包」聚合，不做后台埋点（`D-20261110-030` 已有诊断包基础）。

### 1.4 明确不做

- 社交 / 好友 / 排行榜 / 打卡圈（AESTHETIC §5）。
- 虚拟货币 / 等级 / 成就徽章 / 抽卡（奖励只有积木、建筑、铭文）。
- 账号体系 / 云端存储 / 订阅墙 / 推送营销。
- 彩色主题 / 新色相 / 第三方 UI 库。
- 应用或网站监控、阻断（专注陪伴只做用户自己启动的计时）。
- 未经审批的新依赖（keyring、ZIP 库、图表库等）。

## 3. 详细设计

### A1 桌面摆件：三档尺寸 + 置顶开关（D-20261110-059）

#### 3.1.1 问题与判断

现状：迷你摆件是**主窗口被 setSize 到 260×380** 的临时形态，固定尺寸、固定置顶、退出即恢复设置；用户只有「开 / 关」两个选择。

问题：尺寸决定它能放哪。宽屏用户想把它放在建筑旁边当「工地监工」，小屏/笔记本用户只想要一条进度；固定 260×380 让前者觉得占地方、后者觉得浪费。**摆件不是一个开关，而是一个常驻物件，应该有形态选择。**

#### 3.1.2 三档形态

| 档位 | 逻辑尺寸（含边框） | 放什么 | 适合谁 |
| --- | --- | --- | --- |
| **口袋 Pocket** | 220 × 150 | 标题拖拽条（28px）+ 3D 小窗（~64px）+ 今日 `2/3` + 进度条 + 1 个快捷打卡胶囊 | 小屏 / 只想瞥一眼 |
| **标准 Standard** | 280 × 400（沿用现有 260×380 的内容密度） | 3D 建筑 + 蓝图进度 + 最多 3 个快捷打卡 + 「今日已完成」 | 默认，放在屏幕角落 |
| **展台 Display** | 420 × 560 | 3D 大窗 + 今日清单（最多 5 件）+ 下一里程碑 + 进度 | 双屏 / 大屏 / 展示 |

- 三档都保留：拖拽移动、双击标题展开主窗、关闭收托盘、置顶开关。
- 口袋里不放设置与图鉴入口（避免误触）；双击展开即可。
- 展台不提供编辑习惯，只读展示 + 打卡；编辑仍回主窗。

#### 3.1.3 交互流程

```
标题栏摆件按钮 / 设置 → 迷你摆件
  → 若从未选择过：默认「标准」尺寸 + 置顶关（首次开启置顶时一次性说明「会浮在其他窗口前」）
  → 弹出小面板（主窗内）：三档尺寸缩略图 + 置顶开关 + 「进入摆件」
  → 选择后 setSize( preset ) + 记录上次位置（屏幕右下 24px 边距）
  → 摆件内：双击标题展开 → 恢复主窗原尺寸并居中
  → 关闭（X）：先恢复尺寸再隐藏到托盘（沿用 A10 握手）
```

- 设置持久化：`miniWidgetSize`（'pocket' | 'standard' | 'display'）与 `miniWidgetAlwaysOnTop` 进 `AppSettings`（跨设备同步可接受）；**窗口位置只进 localStorage**（设备本地，不进存档，避免换屏后跑到看不见的地方）。
- 多显示器：启动/进入摆件时用 `currentMonitor().workArea` 把位置钳制在可视区（含任务栏），显示器拔掉后下一次显示重新钳制。
- DPI：所有尺寸用逻辑像素，交给 Tauri 换算物理像素；125%/150% 下不得裁切文字。
- 首次引导：第 1 座建筑落成后，在今日简报或落成弹窗里出现一次「把它放到桌面，每天路过都能看到」的入口（可关，只出现一次）。

#### 3.1.4 视觉规格

- 复用 `--surface / --bg / --line / --r-md / --fs-caption / --fs-small / --fs-body / --r-sm`；无新色相、无新阴影。
- 标题栏 28px，左侧 logo 16px，右侧展开/关闭 icon-btn 24×24；正文 padding 8–12px。
- 3D 区域由现有 `BuildScene` 渲染（不新写渲染逻辑）；口袋档可隐藏植被/环境装饰以省资源（ART 允许的性能取舍）。
- 进度条沿用 3.5px 高、`--line` 轨道、`--ink` / `--progress-green` 填充。

#### 3.1.5 技术方案与边界

- 改造 `App.toggleMini` 为接受 size preset；主窗尺寸恢复逻辑保留；`resizable=false` 不变（避免用户拖成四不像）。
- 摆件内容组件 `MiniDeskToy` 增加 `size` prop，按档位渲染不同区块；共享现有快捷打卡 action。
- 关闭 / 托盘 / 重启：沿用现有 `enableMiniWidget` 语义（手动退出写回 false；关闭 = 恢复后隐藏）。
- 权限与最小尺寸（技术校订）：新增 capabilities `core:window:allow-set-min-size` 与 `core:window:allow-set-position`；进入前先 `setMinSize(preset)` 再 `setSize`，退出恢复 `900×600`（tauri.conf 的最小尺寸），不依赖隐式行为；手动进入摆件时写回 `enableMiniWidget:true`（现有代码只在自动进入时判定，重启不会回到摆件）；迷你件 24×24 按钮与 3px 胶囊命中区一并提升到 ≥32px（审计 U21）。
- 让位：v1 用「置顶默认关 + 不自动弹出 + 空闲零重绘」实现不打扰；全屏应用自动隐藏需要检测前台全屏（系统 API），不在 v1 范围，列为 v2 观察项。
- 失败模式：显示器拔掉（重新钳制）、DPI 变化（逻辑尺寸重算）、主窗最大化后再进摆件（先记录原尺寸）、多实例（单实例已保证）、任务栏自动隐藏（工作区变化）。
- 不做：透明/异形窗口、桌面层嵌入（Wallpaper Engine 式）、鼠标穿透、桌面宠物动画。

#### 3.1.6 验收标准

1. 三档在 100%/125%/150% 缩放下无文字裁切、无横向滚动；双屏切换后位置仍在可视区。
2. 口袋档可完成一次快捷打卡；标准档显示 3D 与蓝图进度；展台档显示今日清单。
3. 尺寸与置顶选择刷新/重启后保持；位置保持；关闭后再开恢复主窗原尺寸。
4. 空闲时无持续重绘（复用渲染层的「无变化不重绘」）；内存 ≤ 现有迷你件 +20%。
5. 四主题截图无新色相；i18n zh/en 完整；reduced-motion 下无动画。

#### 3.1.7 工作量与风险

- 工作量：**S**（1–2 人日；主要是窗口逻辑与三档布局，渲染复用）。
- 风险：多显示器/DPI 边界（中）；摆件常驻的「注意力打扰」争议（低—可关闭即可）；用户误以为摆件是独立小窗（低—双展开说明）。

### A2 落成年鉴：把一年的坚持做成一件作品（D-20261110-060）

#### 3.2.1 问题与判断

现状：统计页 = 每习惯热图 + 手账长廊；月度画报 = 单月海报；拍立得 = 单座落成纪念。**没有一个「这一年」的东西**。

年度回顾类功能被验证能显著提升分享与回访（Spotify Wrapped、Strava Year in Sport、GitHub Wrapped、Letterboxd Year in Review 的共同点：把用户自己的数据变成一段可回看、可展示的叙事）。但 BlockHabit 的版本必须遵守本地优先：**不自动生成云端对比、不做「你超过了 87% 的人」、不做社交分享链路**；分享只能是用户自己保存一张图。

#### 3.2.2 产品形态：不是统计页，是「年鉴」

- 入口：统计页右上角「年鉴」按钮（与「月度画报」「修复积木」并列）；**一年只在首次打开时出现一次角标**，不自动弹窗。
- 形态：全屏弹层（`YearbookModal`），左侧年份列表（有数据的年份），右侧画布预览 + 导出按钮。
- 内容按「书页」组织，可上下滚动，导出为一张竖版长图或一组页面图：

| 页 | 内容 | 数据来源 |
| --- | --- | --- |
| 封面 | 年份 + 「第 N 年」+ 当年落成建筑剪影 + 一句数据生成的话 | builds / checkIns |
| 这一年 | 打卡次数、积木数、落成建筑数、全勤天数、最长连击、专注小时、随笔数 | checkIns / dayClaims / builds / habits |
| 十二个月 | 12 个月热图（灰阶），标注全勤日与最长连击段 | checkIns |
| 建筑年表 | 每座落成日期 + 等距缩略图 + 奠基石铭言（有则显示） | builds / foundationNotes |
| 时间形状 | 最常打卡时段、最常打卡星期、Top 3 习惯（只陈述，不评分） | checkIns / habits |
| 一句话 | 从当年随笔中按规则挑一条（最长、最早、星标优先），署名习惯名 | checkIns.note |

- 文案规则（VOICE）：只陈述事实与时间，不做评价（禁止「你退步了 / 你太棒了」）；没有数据就显示「这一年还没有落成」。

#### 3.2.3 交互流程

```
统计 → 年鉴（角标）
  → 默认当前年；若无数据，显示空态 + 切换年份
  → 预览画布（按窗口宽度等比缩放，最大 720px 宽）
  → [保存图片] [复制图片] [导出 Markdown] [关闭]
  → 导出时若字体未就绪，先 await document.fonts.ready，避免 CJK 缺字
```

- 移动端（实验形态）：全屏 sheet，画布宽度 100%，按钮改为底部双按钮。
- 无障碍：年份列表为 tablist；画布有 `aria-label` 文本摘要（完整内容也可读屏）；导出按钮有可访问名称。

#### 3.2.4 数据与逻辑

- **不新增持久化字段**：全部从现有 `AppState` 派生（`checkIns` 排除墓碑、`builds` 按 `placedAt` 年份、`dayClaims`、`foundationNotes`、`repairBricks`）。
- 新纯逻辑 `src/logic/yearbook.ts`：
  - `availableYears(state): number[]`
  - `buildYearbook(state, year, lang): YearbookModel`（统计、月热图、建筑年表、Top 习惯、引用随笔）
  - `yearbookSummary(model): string`（供 aria 与 Markdown 导出）
- 时间口径：日期键已是本地时区 `YYYY-MM-DD`，按字符串前缀取年份，避免时区漂移。
- 删除/撤销：`deletedAt` 的打卡与积木不计入；与统计页保持同一口径。
- 跨设备合并：只统计本地合并后的最终状态（与今日页一致），不标记来源设备。

#### 3.2.5 渲染与导出

- 复用月度画报的「印刷感」语汇：纸白底、墨色字、网格、1px 线、无渐变；点缀色只用于「落成 / 完成」的小标记（A1）。
- 新画布模块 `src/render/yearbookCanvas.ts`：接收 `YearbookModel` 与主题令牌绘制；四主题各一张；字体用现有离线字体（Rubik / MiSans / 数黑体），不新增字体。
- 导出：PNG（竖版 1080×1920 / 横版 1600×1200 两档，用户二选一）；另导出 Markdown 文本（便于贴进任意笔记软件，不依赖本应用）。
- 画布尺寸与 DPR：按 2× 渲染、保存时用物理像素；不做超长 12 屏拼接（体验差、内存高），改为「封面 + 建筑年表」一张，其余页可另存。

#### 3.2.6 取舍与被否方案

- **否掉自动弹窗**：一年一次也仍然是打断；角标 + 入口足够，用户主动打开才有仪式感。
- **否掉 AI 生成文案**：引入联网/模型依赖，违背 A7；用规则模板 + 用户自己的随笔。
- **否掉社交分享（链接/排行）**：AESTHETIC §5；只导出本地图片。
- **否掉医疗化/心理评价**：不做情绪打分、不做「幸福感趋势」。
- **否掉把所有历史年混在一起**：年鉴必须按年切分，否则没有「这一年」的边界。

#### 3.2.7 验收标准

### A3 WebDAV 预设 + 连接自检（D-20261110-061）

#### 3.3.1 问题与判断

现状：设置页有「WebDAV 地址 / 用户名 / 密码 / 自动同步 / 立即同步」，凭据存 localStorage，错误码映射为少量人话；对普通用户来说，**URL 该填什么、要不要 App Password、为什么 401、是不是被 CORS 拦了**仍然是黑箱。

多设备同步是「敢不敢长期用」的关键承诺；同步配置门槛直接决定这个承诺是否成立。竞品（Joplin、Obsidian Remotely Save）都把「服务商预设 + 应用专用密码 + 测试连接」作为标配。

#### 3.3.2 产品形态

```
设置 → WEBDAV 数据同步（折叠组）
  ① 选择服务商：[Nextcloud] [坚果云] [群晖] [通用 WebDAV]
  ② 填写：服务器地址（预设时只需域名）、用户名、应用专用密码
     └ 预设自动生成 endpoint；提示「不要用登录密码，去后台创建应用密码」
  ③ [测试连接] → 分步结果（见下）
  ④ 通过后：[立即同步] [自动同步开关] [清除凭据]
```

**分步自检**（每步一行，成功 ✓ / 失败 ✕ + 人话 + 下一步）：

| 阶段 | 做什么 | 失败提示示例 |
| --- | --- | --- |
| 1 地址 | 规范化 URL、补全协议与尾斜杠 | 地址不是 http(s) URL / 无法解析主机 |
| 2 连接 | HEAD/PROPFIND 根路径，验证 TLS 与可达 | 证书不受信任 / 服务器拒绝连接 / 超时 |
| 3 认证 | PROPFIND with Basic Auth | 401：用户名或应用密码错误；403：无权限；可能需应用专用密码 |
| 4 读写 | PROPFIND 目标目录 → PUT 临时文件 → GET 读回 → DELETE | 404 目录不存在（一键创建？）/ 507 配额不足 / 405 不允许 PUT |
| 5 清理 | 删除临时文件，报告总耗时 | 删除失败：请手动清理 `blockhabit-test-*.json` |

- 临时文件名带时间戳与随机串，避免碰撞；所有阶段 10s 超时、可取消。
- 浏览器预览（`npm run dev`）：仅显示「浏览器环境受跨域限制，请用桌面端连接」，不发起测试（与现有诚实降级一致）。
- 错误详情可折叠复制，**不得包含密码**；URL 中的 userinfo 若存在要脱敏。

#### 3.3.3 预设数据

`src/sync/providers.ts`：

| id | 名称 | endpoint 生成 | 备注 |
| --- | --- | --- | --- |
| nextcloud | Nextcloud | `{base}/remote.php/dav/files/{username}/BlockHabit/` | 必须应用密码（2FA 下登录密码无效） |
| jianguoyun | 坚果云 | `https://dav.jianguoyun.com/dav/BlockHabit/` | 使用「第三方应用密码」 |
| synology | 群晖 WebDAV | `{base}/home/BlockHabit/`（按套件路径可改） | 需在套件中心启用 WebDAV Server |
| generic | 通用 WebDAV | 用户手填完整 URL | 提示尾斜杠与目录需已存在 |

- 预设只存「服务商 id + base + username」，不存密码副本；切换预设时清空旧 endpoint 并提示。

#### 3.3.4 技术方案

- 复用 `src/platform/http.ts`（桌面原生 HTTP，绕 CORS）与 `src/sync/webdav.ts` 的请求封装；新增 `src/sync/diagnose.ts`（阶段计划 + 结果归类，纯函数，注入 transport 便于测试）。
- 新增 `src/sync/providers.ts`（纯数据 + endpoint 生成函数，单测覆盖 URL 拼接/编码/尾斜杠）。
- 现有 `WebDavError` 错误码映射到阶段结果；新增 `auth` / `forbidden` / `not-found` / `quota` / `method-not-allowed` / `tls` / `timeout` 的人话文案（i18n）。
- 凭据安全：当前密码在 localStorage（与现有实现一致）。**本轮不改存储方式**；UI 明示「密码保存在本机，仅建议使用应用专用密码」，提供「清除凭据」。keyring 需要新依赖，单独立项（D-048 决议 5 的同类问题）。
- 自检不写入正式同步文件；失败不影响现有自动同步配置。

#### 3.3.5 取舍与被否方案

- **否掉「自动探测服务商」**：需要请求第三方、泄露端点，且不可靠；预设置为准。
- **否掉 OAuth**：WebDAV 没有统一 OAuth，且会引入联网账号依赖（A7）。
- **否掉把密码搬进系统钥匙串（本轮）**：新依赖 + 迁移成本，收益小于先把连通性做对。
- **否掉隐藏错误细节**：用户需要能复制给服务商排障；但必须脱敏。

#### 3.3.6 验收标准

1. `providers.test.ts`：四种预设 endpoint 生成（含用户名编码、尾斜杠、切换清空）。
2. `diagnose.test.ts`：注入 mock transport，覆盖 200/401/403/404/405/507/超时/TLS 失败；结果阶段与文案正确；错误文本不含密码。
3. 真实 Nextcloud / 群晖至少各连通一次（人工验收），404 目录场景给出可执行下一步。
4. 浏览器预览不发起请求，显示桌面端提示；桌面端无 CORS 问题。
5. 四主题 + zh/en 截图；键盘可完成全流程；`tsc` / `npm test` / `design:check` 通过。

#### 3.3.7 工作量与风险

- 工作量：**S**（1–2 人日；诊断逻辑 + 预设 + 设置 UI）。
- 风险：真实服务器差异（中—先支持 2 个主流服务商并保留通用项）；密码明文存储（中—文档明示 + 应用密码指引，keyring 另立记录）；TLS 自签证书（低—明确报错而非静默失败）。

### A4 一键档案包：把多年数据变成「拿走就能读」的东西（D-20261110-062）

#### 3.4.1 问题与判断

现状：可以导出 JSON、可以做应用内备份、可以打开数据目录；但这些对普通用户都不是「拿走就能读」。真正的数据主权需要三件事同时成立：**能带走（导出）、能读懂（人可读）、能验证（完整未被篡改）**。

Apple Health / Spotify / Strava 的批量导出之所以被信任，是因为它们给的是「文件夹 + 结构化数据 + 说明」而不是一个二进制黑箱。BlockHabit 应该给一份**可读的档案馆**，而不是再来一个 JSON。

#### 3.4.2 档案包内容

```
BlockHabit-Archive-2026-11-10T1030Z/
├─ README.md                 人读说明（什么是 BlockHabit、这份档案包含什么、如何恢复）
├─ manifest.json             应用版本 / schemaVersion / 导出时间 / 文件清单 / 每文件 sha256
├─ data/
│  ├─ blockhabit-state.json  与「导出数据」完全相同的可导入 JSON
│  └─ checksums.txt          每文件 sha256（便于外部校验）
├─ buildings/
│  ├─ 01-plant.png           已落成建筑的等距渲染图（透明背景 2×）
│  ├─ ...                    12 座（未落成不导出，或导出当前在建的「进度图」）
│  └─ README.md              建筑名 / 落成日期 / 奠基石铭言
└─ yearbook/                 若存在年度年鉴（可选，A2 完成后）
   └─ 2026.png
```

- README 用人话写：数据在哪、怎么用应用恢复、建筑对应哪一年、如何校验。
- 图片用现有等距渲染（`drawCube` / `BuildScene` 的离屏绘制能力），透明背景、2×、固定取景，保证十年后仍能看懂。
- **不上传、不联网、不含任何账号信息**；WebDAV 凭据绝不进档案包。

#### 3.4.3 交互流程

```
设置 → 数据安全 → [导出完整档案包]
  → 选择内容（默认全选）：数据 / 建筑图 / 年鉴（若可用）
  → 生成进度（建筑渲染逐座进行，可取消）
  → 完成：显示「档案包已生成」+ 文件大小 + [打开文件夹]
  → 失败：保留已完成部分并说明（可重试）
```

- 桌面端：写到 `appDataDir/exports/BlockHabit-Archive-<timestamp>/`，用现有 `openDataDir` 能力打开所在目录（不引入 dialog 插件）。
- 浏览器端（dev/preview）：逐文件下载（浏览器会询问多次保存）；提示「桌面端会打包为一个文件夹」。
- 不做云端上传、不做分享链接。

#### 3.4.4 格式决策（技术笔记已确认可行）

- **权威产物 = 文件夹**：无新依赖、可增量、失败可续、用户可直接打开看；桌面端写到 `appDataDir/exports/BlockHabit-Archive-<timestamp>/`，先写 `.tmp-archive-<stamp>` 成功后 rename，失败/取消清理。
- **可选 ZIP**：无依赖 STORE+CRC32 约 150–180 行纯 TS（实测 8MB CRC 13ms）；文本文件可用 `CompressionStream('deflate-raw')` 做 method 8，缺失时 try/catch 降级为 STORE。ZIP 只作「方便发给别人/上传网盘」的副本，不替代文件夹。
- **浏览器端固定产出单个 ZIP**（一次交互、结构不散、校验清单在内）；「逐文件下载」作为兜底选项。
- 桌面端「打开文件夹」用 `revealItemInDir`（`opener:default` 已含，无需新权限）；顺手修掉现有 `openDataDir()` 的权限坑（它用 `openPath`，但 capabilities 未授 `opener:allow-open-path`，可能静默失败）。
- 新增 capability：`fs:allow-write-file`（与 A1 的两条窗口权限合并成一次评审）。
- 无论哪种，`data/checksums.txt` 与 `manifest.json` 必须存在，保证可校验。

#### 3.4.5 技术方案与边界

- 复用 `exportData()`（现有）生成 state JSON；复用 `backups` 的目录/打开目录能力；建筑图用离屏 canvas 渲染（不截图 UI，避免主题/窗口尺寸污染）。
- 生成过程分片（每座建筑 `await` 一帧），避免长任务阻塞界面；进度条 + 取消。
- 边界：没有落成建筑（只导出数据 + 空 buildings 说明）；磁盘空间不足（失败并清理半成品）；文件名含中文/空格（Windows 合法，但 README 说明）；多年后 schema 升级（manifest 记录 schemaVersion，README 说明向下兼容策略）。
- 兼容：`data/blockhabit-state.json` 必须能被现有「导入数据」直接读回（round-trip 测试）。

#### 3.4.6 取舍与被否方案

- **否掉只导出 JSON**：普通用户读不懂，也不算「档案」。
- **否掉截图整个应用界面**：含主题/窗口尺寸/DOM，长期看不可读。
- **否掉加密 ZIP**：密码丢失即数据丢失，且要处理 KDF；本地明文 + 用户自己保管更符合本地优先。
- **否掉自动上传到云盘**：A7；用户可自己把文件夹放进同步盘。

#### 3.4.7 验收标准

1. 档案包生成成功：manifest 文件清单 + 每文件 sha256 与 checksums.txt 一致；`data/state.json` 导入 round-trip 后与导出前数据一致。
2. 建筑图：已落成数量正确、透明背景、2×、文件名与蓝图 id 对应；未落成建筑不产生误导性「已完成」图。
3. 中断/取消/磁盘错误：不留半成品或明确标注 incomplete；再次导出可覆盖。
4. 浏览器回退逐文件下载可用（至少 state.json + README）。
5. 四主题与 zh/en 文案；`tsc` / `npm test` / `design:check` 通过。

#### 3.4.8 工作量与风险

- 工作量：**M**（2–4 人日；离屏建筑渲染 + 文件组织 + 校验 + 浏览器回退）。
- 风险：离屏渲染的字体/DPR 差异（中—固定 2× 与字体就绪）；Windows 路径长度（低—短目录名）；用户误以为档案包可直接编辑（低—README 说明只读快照）。

### B1 内容二期：扩展蓝图包（D-20261110-063）

#### 3.5.1 问题与判断

12 座 1385 块，按「1 习惯 ≈ 2 块/天」约 **693 天** 封顶；全部落成后打卡仍记录但不再掉块（已有诚实提示）。这不是 bug，是**有限内容产品的自然终点**，也是 BlockHabit 与「无限任务」类产品的结构性差异。

竞品用无限任务掩盖内容枯竭；BlockHabit 必须正面设计「第 191 天之后」。

#### 3.5.2 三个选项与建议

| 选项 | 做法 | 优点 | 风险 | 判断 |
| --- | --- | --- | --- | --- |
| ① 免费年度扩建包 | 每年随版本内置 4–6 座新蓝图（约 400–600 块） | 离线、无商店、无支付；持续给长期用户期待 | 美术/设计成本；老客户端兼容 | **推荐先做** |
| ② 付费 DLC | 内容包单独售卖 | 收入 | 需商店/支付/签名/发票/退款；与「本地优先」信任冲突 | 暂不做（签名与分发前置完成后再评估） |
| ③ 自由建造 / 装饰模式 | 全落成后解锁拆改、装饰件、第二张桌子 | 无限内容、复用美术 | 变成 sandbox，可能稀释「时间形状」 | 作为 ① 的补充，不做主线 |

**建议**：0.5.0 做「免费年度扩建包（第一批 6 座）+ 全落成后的自由装饰模式」，内容随安装包内置，不联网下载。一年一更，节奏写入 README/设置页「内容路线」。

#### 3.5.3 内容设计约束

- **总和而非替代**：12 座现有蓝图不删不改（AGENTS 铁律）；新包只追加，`blueprintOrder` 末尾扩展。
- 主题：现有从「绿意盆栽 → 灰岩城堡」是「从小物件到建筑」的成长叙事；二期建议转向「城市与生活」：街角书店、面包房、水塔、钟楼、车站、温室（6 座，约 400–600 块）。
- 美术：沿用等距积木语言；新颜色只能走 `ART.md` 的装饰色例外（D-048 决议 3），不得新增主题色。
- 容量：每座 40–120 块，避免单座过长；总时长约 +150–250 天。
- 每座需要：蓝图数据、i18n 名称、图鉴缩略图、落成文案、可能的生态彩蛋位。

#### 3.5.4 版本兼容（最关键）

新增蓝图 id 会让**旧客户端**遇到未知 id。现有 `getBlueprint` 会回退到 plant，可能导致渲染错误/进度错误，且同步会把新数据带到旧设备。必须设计：

1. `AppState` 增加 `contentVersion?: number`（或复用 schemaVersion 的次版本策略）；旧客户端加载到更高 `contentVersion` 时，**挂起持久化 + 只读提示升级**（复用 `needsUpgrade` 机制），避免破坏新数据。
2. 旧客户端若仍写入（用户拒绝升级）：未知 blueprint 的 builds 保留原样、不参与渲染与容量计算；今日页提示「数据来自更新版本」。
3. 同步合并：墓碑与事实重建必须保留未知 blueprint 的记录（当前 `rebuildBuilds` 依赖蓝图注册表，需按「保留未知」改造）。
4. 图鉴/进度：总数动态取自 `blueprintOrder.length`；`completedBlueprintIds` 里未知 id 不清除。
5. 迁移测试矩阵：旧客户端 × 新存档、新客户端 × 旧存档、双端同步、回滚安装。

> 这是 B1 真正的技术难点，工作量主要不在画蓝图，而在兼容性。必须在实现前单独写一条「内容版本与旧客户端兼容」记录（可拆自 D-063）。

#### 3.5.5 交互与文案

- 新包发布后：图鉴里出现「待解锁」的新建筑（不提前显示完整造型，只显示剪影与名字）；当前 12 座全落成时，建造页从「全部落成」切换为「扩建包已就绪」。
- 不制造 FOMO：不显示倒计时、不做限时；内容永久留在安装包里。
- 「内容路线」说明放在设置页「关于」区域：已发布/计划中的包，诚实说明节奏。

#### 3.5.6 验收标准

1. 新增 6 座蓝图通过生成器单测（坐标唯一、容量正确、图标可渲染）。
2. 兼容矩阵 5 项全过（见 3.5.4），旧客户端不丢新数据、新客户端不读坏旧数据。

4. 升级/降级安装 + 同步合并的自动化测试；`tsc` / `npm test` / `design:check` 通过。
5. 新建筑四主题截图、性能基线不回退（190 块场景仍达标）。

#### 3.5.7 工作量与风险

- 工作量：**L**（内容生产 6–10 人日 + 兼容改造 4–6 人日）。
- 风险：兼容性（高—必须先做版本门）；美术成本（中—需人工审定）；用户预期管理（中—诚实路线图）；商业化边界（高—先免费，避免信任透支）。

### B2 桌面专注陪伴（D-20261110-064）

#### 3.6.1 问题与判断

现有专注习惯：点卡片开始倒计时 → 到点进入「待确认」→ 再点完成打卡。倒计时只存在于今日页的卡片里；一旦切走页面或收起窗口，专注就「看不见了」。

而桌面摆件正好可以承担「陪着你专注」的角色——**不监控你在干什么，只显示你自己启动的计时**。这与 Focus Bear 的阻断/监控形成价值观上的明确区隔。

#### 3.6.2 产品形态

摆件在专注时切换为「专注模式」（三档尺寸各有布局）：

| 状态 | 触发 | 摆件显示 |
| --- | --- | --- |
| idle | 没有进行中的专注 | 今日进度 + 3D 建筑 + 快捷打卡（现有） |
| focusing | 用户在某习惯上开始专注 | 习惯名 + 倒计时 + 环形进度 + 「放弃」小按钮（需确认） |
| ready | 倒计时到点 | 「时间到，落一块？」+ [完成打卡] [再等 5 分钟] |
| done | 确认完成 | 落块动画 + 新建筑进度 + 自动回 idle（声音尊重静音） |

- 口袋档只显示「倒计时 + 环形进度 + 完成按钮」；标准/展台档显示 3D 建筑（专注时建筑微微「施工中」状态？不做循环动画，遵循 A5）。
- 多习惯同时专注（现有允许）：摆件显示**最早结束**的一个，其余在展开主窗可见。
- 托盘 tooltip 可显示「专注中 · 12:30」；不做系统级番茄钟接管。

#### 3.6.3 交互流程

```
今日页专注卡片 [开始专注] / 摆件快捷入口
  → 会话写入 timerStore + localStorage（habitId / startedAt / targetMs）
  → 摆件自动切换 focusing
  → 到点：通知（可选）+ 摆件 ready
  → [完成打卡] → 现有 checkIn(habitId, actualMinutes) → 落块 → done
  → [再等 5 分钟] → 延长 targetMs（只允许 1–2 次，避免无限拖延）
  → [放弃] → 二次确认 → 会话清除，不产生打卡
```

- 关闭应用后再打开：从 localStorage 恢复会话；若已超时，进入 ready 并提示「离开期间计时已结束」。
- 跨午夜：`startedAt` 是绝对时间，不受日期翻转影响；打卡日期取确认时 `todayKey`（与现有行为一致，需在记录里明确）。
- 不做：后台常驻计时服务（应用退出即暂停？——不，绝对时间继续走，但只有打开时才能确认）、拦截其他应用、网站屏蔽、摄像头/麦克风。

#### 3.6.4 数据与技术

- 现状：`timerStore` 仅内存态（`Record<habitId, {startedAt,targetMs}>`）。改为：内存态 + localStorage 持久化（设备本地，不进存档/同步，避免多设备互相干扰专注会话）。
- 新纯逻辑 `src/logic/focusSession.ts`：`remainingMs(session, now)`、`phase(session, now)`（focusing/ready/expired）、`extend(session, minutes)`、`shouldRestore(saved, now)`；单测覆盖时钟回拨/超时/跨午夜。
- 摆件组件读取 `timerStore`，按 phase 渲染；现有 `TimerWatcher` 负责通知（避免重复）。
- 完成打卡复用 `checkIn(habitId, actualMinutes)`；`actualMinutes` 用实际经过分钟（向上取整，至少 1）。
- 边界：习惯被删除/归档 → 会话清理；目标时长被改 → 会话保留原 targetMs；系统休眠 → 用 Date.now 计算，恢复后正确；多窗口（托盘菜单）不同步会话 → 托盘菜单不显示专注。

#### 3.6.5 取舍与被否方案

- **否掉自动完成打卡**：数据诚实优先；到点只提示，确认才落块（用户可能中途离开）。
- **否掉监控/阻断**：越界且与 A7 冲突。
- **否掉循环动画/呼吸光晕**：A5 禁止无意义循环动效；静态环形进度即可。
- **否掉后台服务**：需要常驻进程/系统权限；现有「应用运行中生效」的诚实限制保留。

#### 3.6.6 验收标准

1. `focusSession.test.ts`：剩余时间、ready、超时恢复、延长、时钟回拨、跨午夜。
2. 开始专注 → 摆件切换；到点 → 通知 + ready；完成 → 落块并写 actualMinutes；放弃 → 无打卡。
3. 关闭应用 → 重开 → 会话恢复；已超时则直接 ready。
4. 三档尺寸显示不裁切；reduced-motion 无动画；静音下无声音；四主题无新色相。
5. `tsc` / `npm test` / `design:check` 通过。

#### 3.6.7 工作量与风险

- 工作量：**M**（2–4 人日；会话持久化 + 摆件状态机 + 通知）。
- 风险：计时语义（中—明确「应用退出不暂停」）；与现有 TimerWatcher 重复通知（中—单一通知源）；摆件尺寸（依赖 A1）。

### B3 建筑即编年史（D-20261110-065）

#### 3.7.1 问题与判断

现在每座建筑落成后：拍立得、奠基石铭言、图鉴缩略图。但**「这座建筑是哪一年、由哪些天组成、当时写了什么」**没有一处完整呈现。打卡随笔已经存在（手账长廊），但和建筑是两套界面。

#### 3.7.2 产品形态：建筑档案卡

在建造页「图鉴」里，点击已落成建筑 → 「建筑档案」（而非直接打开拍立得）：

- 顶部：等距大图 + 建筑名 + 落成日期 + 「第 N 座」
- 数据：总块数、耗时天数（首块→落成）、投入最多的习惯、全勤/奖励块数量
- 时间线：按日期列出该建筑的关键块（首块、每 25%、最后一块），点击看当天打卡与随笔（复用 `BrickInspectPopover` 数据）
- 铭言：奠基石铭言（可编辑，沿用现有弹窗）
- 底部：[拍立得] [保存档案卡 PNG]（与 A2 年鉴共用画布能力）

- 不做新的持久化字段：全部从 `builds`（`blueprintId` + `placedAt` + `fromHabitId`）与 `checkIns` 派生；铭言已存在。
- 与 A2 的关系：A2 是「按年」的总览，B3 是「按建筑」的专辑；年鉴里的建筑年表可链接到档案卡（同一份渲染能力）。

#### 3.7.3 交互与视觉

- 建造页图鉴卡片 → 点击已落成 → 打开 `BuildingArchiveModal`（非全屏，宽 720，可滚动）。
- 视觉沿用「手账 / 印刷」：纸白底、墨色字、1px 线、日期用等宽数字；点缀色只用于「落成日期」小标记。
- 长时间线用分段折叠（每年/每季度），避免一次渲染数百条。

#### 3.7.4 取舍与被否方案

- **否掉给每块积木单独写小传**：数据与输入成本高，且与打卡随笔重复。
- **否掉把编年史做成第三个 tab**：信息架构膨胀；挂在图鉴/年鉴入口即可。
- **否掉新字段 `buildingStory`（v1）**：先证明用户会用；确有需要再加「精选记忆块」字段（需同步设计）。

#### 3.7.5 验收标准

1. 派生逻辑单测：落成日、耗时天数、投入最多习惯、关键块选择、空数据建筑。
2. 图鉴 → 档案卡 → 拍立得/保存 PNG 全流程；键盘可达；Esc 关闭。
3. 100 块建筑的时间线滚动流畅（分段渲染）；四主题 + zh/en。
4. 不新增数据字段；旧存档兼容；`tsc` / `npm test` / `design:check` 通过。

#### 3.7.6 工作量与风险

- 工作量：**M**（2–3 人日；派生逻辑 + 档案卡 + 复用渲染）。
- 风险：与 A2 边界重叠（低—明确「年 vs 建筑」）；时间线性能（中—分段）；用户没有随笔时档案卡显得空（低—只显示有数据的区块）。

## 4. 跨项设计规范（所有创新项共同遵守）

### 4.1 视觉与动效

- 只用 `TOKENS.md` 既有令牌：`--surface / --bg / --line / --ink / --ink-2 / --accent / --r-sm|md|lg|pill / --fs-caption|small|body|subhead|title|hero`。新增表面不得发明数值；先在 `SURFACES.md` 补结构规格，再进代码。
- 新表面仍需遵守 A2（一切都是积木）、A3（只有等距立体）、A4（留白与 1px 线，不堆阴影）、A5（落块物理为主，新动效必须服务物理直觉且尊重 reduced-motion）。
- 不做整页转场、不做循环呼吸光晕、不做彩带以外的装饰粒子。

### 4.2 文案与 i18n

- 所有新文案进 `src/i18n/types.ts` + `zh.ts` + `en.ts`，禁止内联三元（画布绘制例外需注释）。
- 年度回顾、档案、WebDAV 指引这类长文本：先写 zh，再写 en，保持术语表（`VOICE.md`）一致：积木 / 蓝图 / 落成 / 连击 / 全勤 / 修复积木 / 展台 / 年鉴（Yearbook）/ 档案包（Archive）/ 连接自检（Connection Check）。
- 所有「唤起用户」的文案只陈述事实，不做评价、不做倒计时式催促。

### 4.3 无障碍

- 新弹窗沿用 `useDialogA11y`（焦点圈闭、Esc、关闭后焦点恢复）；年份列表用 tablist/roving tabindex；画布有文本替代（aria-label 或隐藏摘要）。
- 所有图标按钮有 `title` + `aria-label`；触达尺寸 ≥ 24×24（桌面）/ 44×44（移动实验形态）。
- 对比度走现有 `--accent-text / --ink` 规则；新画布文字对比度 ≥ 4.5:1。
- reduced-motion：年鉴、档案、专注摆件不得有位移/缩放动画；落块动画沿用全局降级。

### 4.4 数据与隐私

- 不在新功能里加任何网络请求（除可选 WebDAV 自检，且仅在桌面端）。
- 不新增遥测；不做「使用次数上报」；诊断包仍是用户主动导出。
- 档案包 / 年鉴 / 建筑档案均为**本地生成、只读快照**，不自动上传。
- 新增持久化字段必须：进 `types.ts` → `normalizeState` 默认值 → 迁移测试 → `design:check` 记录。能派生就不新增（A2/B3 均不新增数据字段）。

### 4.5 性能预算

| 场景 | 预算 |
| --- | --- |
| 摆件空闲 | 无持续重绘；内存 ≤ 现有 +20% |
| 年鉴生成 | 3 年数据 < 100ms；导出 < 2s |
| 档案包生成 | 12 座建筑图 < 3s，可取消 |
| WebDAV 自检 | 单阶段 ≤ 10s，总 ≤ 30s，可取消 |
| 专注倒计时 | 1s 粒度，不落在 rAF 每帧 |
| 建筑档案时间线 | 首屏 < 100ms，分段渲染 |

## 5. 用户旅程：这些创新如何拼成一个故事

### 5.1 一天

```
早上打开 → 今日简报（还剩几件 / 离落成多远）→ 点「开始第一个」→ 完成 → 落块
白天路过桌面 → 摆件显示 2/3 → 一键打卡 → 积木落下（不打开主窗）
专注习惯 → 摆件变倒计时 → 到点确认 → 落块
晚上 → 若还没完成，自愿开启的收尾提醒出现（每天最多一次）
```

### 5.2 一年

```
每月 → 月度画报（过程）
每座落成 → 拍立得 + 建筑档案（章节）
年末 → 落成年鉴（总结，可保存/可打印）
某天想带走 → 档案包（数据 + 建筑图 + 说明 + 校验）
```

### 5.3 三年

```
12 座落成 → 免费扩建包到货（新 6 座）→ 继续建造
数据一直在本地，可迁移、可校验；换电脑也能带走
```

> 这条旅程的每一环都只服务同一个命题：**让坚持留下看得见的形状**。

## 14. 技术校订与既有缺陷（依据 1485 行技术笔记）

> 本节补充/覆盖上文若干实现细节；若与 §3 有冲突，**以本节与技术笔记为准**。

### 14.1 既有缺陷（Wave 0，建议先修再创新）

调研中在现有代码里发现 3 个与创新无关、但会影响数据可信度的缺陷：

| # | 缺陷 | 证据 | 影响 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | `repairBrickMonth` 未进 `persistState` 与 `useSync.buildLocalState` 的字段白名单 | `appStore.ts` / `useSync.ts` 手工白名单；只在 exportData 与 normalize 出现 | 重启后月度额度结算把「已结算月份」当未知，**重复补修复砖额度（可刷砖）** | 抽 `serializeState()` 共享白名单，三处共用 + 回归测试（0.5 人日） |
| 2 | `openDataDir()` 用 `opener.openPath`，但 capabilities 未授 `opener:allow-open-path` | `backups.ts:134-142`、`src-tauri/capabilities/default.json` | 「打开数据目录」**可能静默失败** | 改用 `revealItemInDir(blockhabit.json)`（已授权）或补权限（0.2 人日） |
| 3 | `zh.ts` 的 CORS 文案仍写「桌面端直连通道还在开发中」 | D-048 已落地原生 HTTP | 文案与实现不符 | 零成本改文案（0.1 人日） |

另有审计已知项：迷你件按钮 24×24 / 胶囊 3px 低于 32px 命中区（U21），在 A1 内一并修。

### 14.2 A1 技术校订

- **置顶默认关**：首次开启时一次性说明「会浮在其他窗口前」；不自动弹出；空闲零重绘（现有渲染层已保证静止不重绘）。全屏应用自动隐藏需要前台全屏检测，列为 v2 观察项。
- **窗口最小尺寸是隐式依赖**：全仓库无 `setMinSize` 调用；260×380 能成立依赖「Tauri 不对程序化 setSize 强制 minWidth 900/minHeight 600」这一隐式行为。必须显式化：进入前 `setMinSize(preset)` → `setSize` → `setPosition`（按当前显示器 workArea 钳制）→ `setResizable(false)`；退出恢复 `900×600` 与最近一次主窗尺寸。
- **capabilities**：新增 `core:window:allow-set-min-size`、`core:window:allow-set-position`；缺失时降级（尺寸仍生效，位置/最小尺寸约束不生效）并 DEV warn。
- **持久化分层**：`miniWidgetSize / miniWidgetAlwaysOnTop / enableMiniWidget` 进 `AppSettings`；主窗与摆件位置进 localStorage `blockhabit.windowLayout.v1`；「当前是否迷你模式」只存内存。手动进入摆件时写回 `enableMiniWidget:true`（现有代码未写，重启不会回到摆件）。
- **布局预算**：`src/platform/miniWindow.ts` 定义预设（pocket 220×150 / standard 280×400 / display 420×560）与不变量（header+stage+footer ≤ h-8）；口袋 1 个胶囊、标准 3 个、展台 5 个；DEV 断言防静默裁切。
- **命中区**：迷你件按钮与胶囊提升到 ≥32px；不影响主窗布局。

### 14.3 A2 技术校订

- **零新字段**已确认；`repairBricks` 只有当前库存、无历史 → 年鉴不做「修复砖使用量」。
- **先抽公共画布**：`src/render/modelStage.ts`（三处重复的 bbox→fit→画家排序→ground→cube），再给年鉴/档案/档案包复用；三处旧实现改调用后必须四主题像素 0 差异。
- **导出前 `await document.fonts.ready`**：仓库当前没有任何等待，CJK 未就绪会掉字/错字重。
- 实测聚合 0.22ms/年（1095 打卡）；区分「月度画报=过程、年鉴=总结、建筑档案=章节」三层。

### 14.4 A3 技术校订

- **自检独立于同步合并**：只做只读校验 + 临时文件读写删，不调用 `mergeAppState`、不写正式同步文件；成功后要有正向文案（Joplin 的 Check 按钮曾因版本升级坏掉，必须有回归测试）。
- **TLS/DNS 只能启发式**：JS 侧拿不到结构化网络错误，按错误文本归类；`http://` 端点会被 CSP 拦（`tauri.conf.json` 只允许 https/wss），需明确文案。
- **401 文案点名两步验证**：提示使用应用专用密码；补自签证书、用户名/密码含特殊字符两类分支。
- **凭据缓解**：应用密码引导 + rememberPassword + 输入不回显 + 清除凭据 + 错误脱敏；不引 keyring。
- **顺手修文案**：zh 的 CORS 旧文案（§14.1 #3）。

### 14.5 A4 技术校订

- **权威产物是文件夹**；ZIP 为可选副本。桌面端写到 `appDataDir/exports/BlockHabit-Archive-<UTC>/`，先 `.tmp-archive-<stamp>` 后 rename；失败/取消清理。
- **ZIP 可行且无依赖**：STORE+CRC32 约 150–180 行纯 TS（8MB CRC 13ms）；DEFLATE 可用 `CompressionStream('deflate-raw')`，必须 try/catch 降级 STORE。
- **浏览器固定输出单个 ZIP**（一次下载、结构不散、校验清单在内）；逐文件下载作为兜底。
- **能力**：新增 `fs:allow-write-file`；打开目录用 `revealItemInDir`（`opener:default` 已含）；顺手修 `openDataDir()`（§14.1 #2）。
- **安全**：导出前断言序列化结果不含 WebDAV 密码/凭据；checksums 只证明完整性，README 明示「未签名，不证明来源」。
- **可回读**：`data/blockhabit-state.json` 必须经 `prepareImport` round-trip 与导出前状态深度相等。

### 14.6 B1 技术校订（阻塞项必须先解）

- **旧客户端会静默丢新建筑数据**：`sanitizeState` 过滤未知 blueprint 的 builds/completed，且下一次自动保存会落盘覆盖；同步侧 `prepareImport` 返回 null → incompatible。
- **必须新增可选 `contentVersion`（不升 schemaVersion）**，门禁在 sanitize **之前**：
  1. `normalizeState`：缺省 1；2. `loadAndMigrate`：高于当前 → `needsUpgrade`（挂起持久化+提示升级+阻止同步）；3. 三处白名单（persist/export/sync）加字段；4. `mergeAppState` 取 max；5. `validateState` 前先处理版本。
- **5 组兼容矩阵**：旧×新档、新×旧档、保存后回旧、双端同步、降级安装。
- v1 采用「门禁 + 旧客户端只读不可用」；「保留未知只读兼容」作为 phase 2（+2–3 人日）。
- 内容包 manifest：`packId / version / schemaVersion / minAppVersion / sha256`；随安装包内置，不做运行时下载。

### 14.7 B2 技术校订

- 会话持久化到 `localStorage: blockhabit.focusSessions.v1`（设备本地，不进存档/同步），含 `habitId/startedAt/targetMs/notifiedAt`；`notifiedAt` 持久化去重并 prune（现有 TimerWatcher 内存 set 重启会重复通知）。
- 托盘 tooltip 只在相位变化时更新（每秒 IPC 不可接受）。
- Chromium 隐藏/最小化时定时器节流，通知可能延迟约 1 分钟；文案诚实说明「应用运行中生效」。
- 红线写进记录：不读前台窗口、不截屏、不统计其他应用、不做专注分、不惩罚中断。

### 14.8 B3 技术校订

- 落成日由 `builds.filter(bp).map(placedAt).max` 推导；`completedBlueprintIds` 合并后按 id 排序，不能当落成顺序。
- 抽 `blockMetaIndex`（与 BuildScene 同源）复用 BrickInspectPopover 的 O(1) 映射；零新字段。
